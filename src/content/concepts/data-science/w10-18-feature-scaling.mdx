Gradient descent works on any features, but it can be very slow when they are on different
scales. Two lines of preprocessing fix that.

## The problem

Slide 27's example:

| feature | range |
| --- | --- |
| `x₁` = size | 0 to 2000 feet² |
| `x₂` = number of bedrooms | 0 to 5 |

A small change in θ₁ shifts predictions by thousands (it multiplies sizes in the thousands); the
same change in θ₂ barely moves them. So `J` is extremely sensitive to θ₁ and nearly flat in θ₂.
Its contours, the left of slide 27, are **long, thin ellipses**.

Gradient descent steps straight downhill, which on a narrow valley means mostly *across* it. It
bounces from wall to wall and creeps along the floor. The course notes put it this way: "θ will
descend quickly on small ranges and slowly on large ranges, and so will oscillate inefficiently
down to the optimum when the variables are very uneven."

## Feature scaling

Make sure features are on a similar scale. Divide each by its range:

```
x₁ = size / 2000           x₂ = bedrooms / 5
```

Both now run from 0 to 1. The contours on the right of slide 27 become nearly **circles**, and
downhill points nearly at the centre.

The target (slide 28) is roughly `−1 ≤ xᵢ ≤ 1`. The notes stress "roughly": these are not exact
requirements. 0 to 3 is fine; −100 to 100 or 0 to 0.0001 is not.

## Mean normalisation

Slide 29 also centres each feature near zero. Replace `xᵢ` with `xᵢ − μᵢ`, where `μᵢ` is the
feature's mean, then divide:

```
xᵢ := (xᵢ − μᵢ) / sᵢ
```

`sᵢ` is the range, max − min, or the standard deviation. The two give different numbers; the
notes say the quizzes use the range and the programming exercises the standard deviation. With
mean size 1000 and 2 bedrooms on average:

```
x₁ = (size − 1000) / 2000          x₂ = (bedrooms − 2) / 5
```

and both land in about −0.5 to 0.5.

**Do not apply it to x₀.** That feature is the constant 1; centring it would make it 0 and remove
the intercept.

Remember to apply the *same* μ and s to new data at prediction time. A new house must be scaled
with the training set's numbers, not its own.

## Debugging gradient descent

The notes add how to tell whether gradient descent is working. **Plot J(θ) against the number of
iterations.** It should fall on every iteration and flatten out.

- **J increases** at any point: α is probably too large (the learning-rate concept). Decrease it.
- **J falls very slowly**: α may be too small, or the features need scaling.
- **Automatic convergence test**: declare convergence when J falls by less than some small amount,
  such as 10⁻³, in one iteration. The notes warn that choosing that threshold is hard in practice,
  which is why the plot is the better check.

> Put features on similar scales, ideally centred on zero, before running gradient descent. Then
> J's contours are round, not narrow, and descent goes straight to the minimum. Plot J against
> iterations to check it is falling.
