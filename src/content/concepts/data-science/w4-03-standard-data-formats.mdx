The lecture starts with a joke: historically, computer scientists would rather share a
toothbrush than a data format. The cost of that attitude is that every data set seems to come
in its own way. Accepted standards now exist, and knowing them saves a lot of parsing.

| Format | Use it for |
| --- | --- |
| **CSV** | Tables, like spreadsheets |
| **XML** | Structured but non-tabular data |
| **JSON** | Data from APIs |
| **SQL databases** | Multiple related tables |
| **Pickle** | Serializing data structures in Python |

## Reading the table

The choice follows the shape of the data. A single flat table is a CSV. Data with nesting —
an item containing a list containing records — is XML or JSON, and JSON is what most web
APIs give you. Several tables linked by a shared key belong in a database. Pickle is
different in kind: it exists to save and reload Python's own objects, so it is convenient
inside a Python project and a poor choice for handing data to someone else.

> Look at the shape of the data first. Tabular, nested, relational or "just my own Python
> objects" each already has a standard answer.
