We want the bottom of `J`. With two parameters we can look at a contour plot; with a hundred we
cannot. **Gradient descent** finds a minimum by walking downhill.

## The outline

From slide 34. Have some function `J(θ₀, θ₁)` and want its minimum.

- Start with some `θ₀, θ₁` (often both 0).
- Keep changing `θ₀, θ₁` to reduce `J`, until we hopefully end up at a minimum.

Picture standing on the surface from the previous concept in fog. You cannot see the bottom,
but you can feel which way the ground slopes under your feet. Take a small step in the steepest
downhill direction, feel again, step again.

## The algorithm

Slide 37:

```
repeat until convergence {
    θⱼ := θⱼ − α · ∂J(θ₀, θ₁)/∂θⱼ        (for j = 0 and j = 1)
}
```

| piece | meaning |
| --- | --- |
| `:=` | assignment: overwrite θⱼ with the new value |
| `∂J/∂θⱼ` | the slope of `J` in the θⱼ direction |
| `α` | the learning rate: how big a step |
| the minus sign | step *against* the slope, which is downhill |

If the slope is positive, `J` rises as θⱼ grows, so θⱼ decreases. If negative, θⱼ increases.
Either way you go down.

## The simultaneous update

There are two parameters, so each round needs two slopes, and **both must be measured at the
same point**. Slide 37 shows the right way and the wrong way:

| correct | incorrect |
| --- | --- |
| `temp0 := θ₀ − α ∂J/∂θ₀` | `temp0 := θ₀ − α ∂J/∂θ₀` |
| `temp1 := θ₁ − α ∂J/∂θ₁` | `θ₀ := temp0` |
| `θ₀ := temp0` | `temp1 := θ₁ − α ∂J/∂θ₁` |
| `θ₁ := temp1` | `θ₁ := temp1` |

In the incorrect version, θ₀ changes before θ₁'s slope is computed. That slope is then taken at
a mixed point: new θ₀, old θ₁. The step is no longer in the steepest direction from where you
stood.

In code, the safe pattern is to compute every new value first and assign them together. With
vectors, `theta = theta - alpha * gradient` does this automatically, which is one reason the
vectorised form from the linear-algebra review is preferred.

## Where you end up depends on where you start

Slides 35 and 36 run gradient descent on a bumpy surface from two nearby starting points. They
roll into **different valleys**. Each is a **local minimum**: lower than everything around it,
but not necessarily the lowest point overall.

This is a real limitation of gradient descent in general. For linear regression it does not
bite, for a reason the last concept in this section explains.

> Gradient descent repeatedly steps each parameter against its slope, scaled by α. All the
> slopes must be computed at the same point before any parameter changes. On a bumpy surface,
> the starting point decides which valley you reach.
