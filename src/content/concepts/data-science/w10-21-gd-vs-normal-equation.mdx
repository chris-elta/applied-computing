Both methods minimise the same `J` and arrive at the same θ. They cost different things.

## The trade-off

Slide 36, for `m` training examples and `n` features, with the costs from the course notes:

| gradient descent | normal equation |
| --- | --- |
| need to choose α | no need to choose α |
| needs many iterations | no need to iterate |
| works well even when n is large | need to compute `(XᵀX)⁻¹` |
| | slow if n is very large |

The cost of inverting `XᵀX`, an `(n+1) × (n+1)` matrix, grows like **O(n³)**. Gradient descent's
cost grows with the number of iterations times the work per iteration, which is far gentler in n.

| n | normal equation, roughly |
| --- | --- |
| 100 | instant |
| 1,000 | fine |
| 10,000 | getting slow |
| 1,000,000 | out of the question |

The notes' rule of thumb: **when n exceeds about 10,000**, it might be time to go from the normal
equation to an iterative method. Below that, the normal equation is usually simpler: no α to tune,
no scaling, no convergence check.

## When XᵀX has no inverse

The linear-algebra review warned that some square matrices are **singular**. `XᵀX` can be one of
them. The notes give two common causes:

| cause | example | fix |
| --- | --- | --- |
| **redundant features**: two are linearly dependent | size in feet² and size in metres² | delete one |
| **too many features**: m ≤ n | 10 houses, 100 features | delete some, or use regularisation |

In both, there is no single best θ: infinitely many fit equally well, so the formula has no unique
answer.

The first case is easy to see. If `x₂ = 0.093 × x₁` exactly, then for any θ you can take some
weight off θ₂ and put a matching amount on θ₁ without changing a single prediction.

The notes' practical advice: compute the inverse with **pinv** rather than **inv**. The
pseudo-inverse returns a sensible θ even when `XᵀX` is singular. But a singular `XᵀX` is also a
signal that your features have a problem worth fixing.

For the too-many-features case, the notes point ahead to regularisation, the subject of the next
section.

> Use the normal equation when n is modest: no α, no iterations, no scaling. Switch to gradient
> descent when n is large, because inverting XᵀX costs O(n³). If XᵀX is singular, look for
> redundant features or too few examples.
