The second half of week 9 turns from showing data to modelling it.

## The pipeline

Slide 54 defines modelling as "the process of encapsulating information into a tool which can
make forecasts or predictions". The key steps are:

1. **build**: choose the model's form, from a first-principles formula to a learned function;
2. **fit**: set its parameters from training data;
3. **validate**: check how well it predicts data it has not seen.

There are many ways to model any data set (slide 55), so you need principles for choosing.
Slide 56 names three: Occam's razor, the bias-variance trade-off, and Nate Silver's habits of
forecasting. Each gets its own concept.

## Occam's razor

The principle states that **the simplest explanation is best**. For a model, "simple" usually
means **fewest parameters**.

The lecture notes give the working version: when two models perform about equally well,
prefer the one with fewer parameters. If a linear model and a deep neural network achieve
similar accuracy, the linear model is typically preferred.

Why should simpler be better, if both fit?

| reason | explanation |
| --- | --- |
| interpretability | you can read four coefficients; you cannot read four hundred |
| generalisation | every extra parameter is another way to fit the noise in the training data |
| robustness | fewer moving parts break in fewer ways when the data shifts |

The second reason is the bias-variance trade-off, coming next.

## Making it mechanical

Slide 57 notes that machine-learning methods like **LASSO and ridge regression** build the
razor into the fitting itself: they add a penalty for large or numerous coefficients, so the
fit has to justify every parameter it uses. Week 10 ends with exactly these methods.

The slide also says to do "a sniff test". A penalty can trim features, but it cannot tell you
whether the features that remain make sense. If a model predicts house prices mostly from
the seller's surname, it needs a human to say that is absurd, however well it scores.

> Between models that predict comparably, choose the one with fewer parameters. It is easier
> to understand and less likely to have memorised noise.
