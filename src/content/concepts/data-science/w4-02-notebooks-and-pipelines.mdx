Suppose you spend a week on an analysis and then someone tells you one of the input files had
a bad month in it. How much of the week do you lose?

If the work lived in a pile of manual edits, nearly all of it. If it lived in a script that
runs from raw file to final plot, you fix the file and run it again.

## Notebooks

A **notebook** (Jupyter is the common one) mixes code, data, computed results and prose in one
document. The lecture says this mixing is essential for a project to be:

- **reproducible** — someone else, or you in six months, can run it and get the same results;
- **tweakable** — change a parameter and see what happens;
- **documented** — the explanation sits beside the code it explains.

The slide's example is a sweep over polynomial degree, with the plot and its interpretation in
the same place as the code that made them.

## Pipelines

A **data pipeline** is the sequence of processing steps from start to finish. Notebooks make
pipelines easier to maintain because every step is visible and ordered.

The instruction attached to this is blunt: **expect to have to redo your analysis from
scratch, so build your code to make it possible.** Data is corrected, new data arrives, a
cleaning decision turns out to be wrong. Redoing is not a failure of planning; it is the
normal case.

> Treat the analysis as a program, not a series of clicks. If you cannot rerun it from raw
> input, you cannot fix it.
