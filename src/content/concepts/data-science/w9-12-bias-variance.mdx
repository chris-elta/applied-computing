> All models are wrong, but some models are useful. — George Box

A model is a simplification, so it will make errors. Slide 58 splits those errors into two
sources that pull against each other.

## Two kinds of error

| | bias | variance |
| --- | --- | --- |
| what it is | error from **erroneous assumptions** in the model | error from **sensitivity to small fluctuations** in the training set |
| typical cause | too simple, such as forcing a straight line | too flexible, such as a curve through every point |
| name for the failure | **underfitting** | **overfitting** |
| how it looks | bad on training data *and* new data | excellent on training data, bad on new data |

A concrete picture: fit house prices against size.

- A **horizontal line** (predict the average price for every house) has high bias. Whatever
  sample you train on, it gives nearly the same line, and that line is wrong.
- A **wiggly curve** through every training point has high variance. Swap one house for
  another and the curve changes shape completely. On new houses it guesses wildly.
- A gently rising line or curve sits between: wrong in the details, stable across samples,
  and useful.

## The trade-off

Adding flexibility lowers bias and raises variance. Removing it does the opposite. The goal,
in the lecture notes' words, is "a balance where the model captures underlying patterns
without memorising noise". Occam's razor is a rule of thumb for this: start simple, and add
complexity only while it keeps improving performance on data the model has not seen.

You can only tell which side you are on by testing on such data. That is why the evaluation
concepts later this week insist on out-of-sample testing.

## Which models suffer which

The slide ends with a useful generalisation:

- **first-principles models** (built from theory) are more likely to suffer from **bias**:
  the theory leaves something out;
- **data-driven models** (learned from correlations) are in greater danger of
  **overfitting**: with enough flexibility, they will find patterns in noise.

Week 10's regularisation is a direct tool for this trade-off: it lets a flexible model keep
its features but pay for using them.

> Bias is being consistently wrong; variance is being inconsistently right. Too simple a model
> underfits, too flexible a model overfits, and only data the model has not seen tells you
> which one you have.
