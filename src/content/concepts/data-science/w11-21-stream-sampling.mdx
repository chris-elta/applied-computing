Every sampling method so far assumed you could see the whole data set: you knew how many
records there were and could visit any of them. A **stream** takes that away. Records arrive
one at a time, you cannot store them all, and you do not know how many are coming.

Slide 15 poses the problem: keep a **uniform sample of size `k`** from a stream when `n` is
not known in advance. Uniform means that whenever the stream stops, every element seen so
far had the same chance of being in the sample.

Random sampling with a fixed probability `p` will not do. To end with `k` records you would
need `p = k/n`, and you do not know `n`.

## The algorithm

Keep an array of `k` elements.

1. The first `k` arrivals fill the array.
2. When element number `n` arrives (with `n` greater than `k`), admit it with probability
   `k/n`.
3. If it is admitted, choose one of the `k` positions at random and replace what is there.

Later arrivals are admitted less and less often: `k/n` shrinks as `n` grows. That is correct.
Once a million elements have passed, a newcomer deserves only a `k`-in-a-million chance.

Memory use is `k` slots however long the stream runs, and each element is handled once.

## Why it is uniform

Slide 16 gives the argument by following element 1.

Assume the method is correct after `n − 1` arrivals, so element 1 is in the sample with
probability `k/(n−1)`. Now element `n` arrives. Element 1 survives in two ways:

| what happens | probability |
| --- | --- |
| `n` is not admitted | `(n − k)/n` |
| `n` is admitted but replaces someone else | `(k/n) × (k−1)/k = (k−1)/n` |
| **total chance of surviving** | `(n − k)/n + (k − 1)/n = (n − 1)/n` |

So:

```
P(1 in sample after n) = k/(n−1) × (n−1)/n = k/n
```

The `(n−1)` cancels. Element 1 has probability `k/n`, exactly the probability with which
the newcomer was admitted. The same reasoning applies to every earlier element, so all `n`
elements are equally likely to be in the sample. Since that holds at each step given that it
held at the step before, it holds for the whole stream.

## A small case

Take `k = 2`. After the first two arrivals both are in the sample with probability 1, which
is `2/2`. Element 3 is admitted with probability `2/3`. Element 1 survives if 3 is rejected
(`1/3`) or if 3 is admitted and evicts element 2 (`2/3 × 1/2 = 1/3`). Total `2/3`, the same
as element 3's chance. All three stand at `2/3 = k/n`.

> To sample `k` items uniformly from a stream of unknown length, admit the `n`-th item with
> probability `k/n` and have it replace a random current member. Every item seen then has
> the same `k/n` chance of being held.
