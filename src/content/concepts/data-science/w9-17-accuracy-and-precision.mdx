Using the four counts from the previous concept, the obvious score is the fraction you got
right. This concept shows why it fails exactly when it matters most.

## Accuracy

```
accuracy = (TP + TN) / (TP + TN + FP + FN)
```

Correct predictions over all predictions. In the screening example:

```
accuracy = (40 + 890) / 1,000 = 0.93
```

93% sounds good. Now meet the baselines.

## The monkey and the sharp

Slide 71 imagines a **monkey** that guesses positive with probability 0.5. Whatever the data,
it gets about half right: 50% accuracy. Slide 71 also notes that **picking the biggest class
always yields at least 50%**.

In the screening example, the biggest class is "no cancer". A model that always says *no*
gets 950 of 1,000 right:

```
accuracy(always no) = 950 / 1,000 = 0.95
```

It beats the 93% model on accuracy while finding **none** of the 50 cancers. This is the
slide's warning:

> When |P| ≪ |N|, accuracy is a silly measure.

With unbalanced classes, accuracy is dominated by the large class, so a model can score highly
by ignoring the small one, which is usually the one you care about.

## Precision

Precision asks a narrower question: **of the cases the model called positive, how many
were?**

```
precision = TP / (TP + FP)
```

In the example:

```
precision = 40 / (40 + 60) = 0.40
```

Six out of ten patients the model flags are false alarms.

Slide 72 points out how hard precision is with unbalanced classes. If only 5% of patients
have cancer, the monkey's flags are a random half of the population, so 5% of them are real:
**5% precision**. So is a "sharp" who always says cancer. Precision exposes them both. But
getting precision *high* needs the model to be very selective, because each positive is
surrounded by nineteen negatives that could become false alarms.

## What precision misses

Precision ignores the cancers the model failed to flag. A model that flags just one patient,
correctly, has 100% precision and misses 49 cancers. The FN count needs its own measure:
recall, next.

> Accuracy rewards getting the big class right, so with unbalanced classes it can be high for
> a useless model. Precision asks how many of your positives were real, which is the first
> step toward a fair score.
