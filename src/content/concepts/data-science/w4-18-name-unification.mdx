The lecturer's own name appears on the web as **(Steve | Steven | Stephen | S.) (S. | Sol | _)
(Skiena | Skeina | Skienna)**. A system that compares strings exactly sees dozens of different
people. The PubMed spike from earlier came from the same problem in a milder form: "F Riahi"
and "Fatemeh Riahi".

## Two kinds of tool

- **Simple transformations**: lower-casing, removing middle names, and similar rules.
- **Phonetic hashing**: **Soundex** and **Metaphone** assign names a code by sound, so
  spelling variants that sound alike get one code.

## The tradeoff

**There is a tradeoff between false positives and false negatives.**

| Matching rule | Effect |
| --- | --- |
| Strict | Few false positives, many false negatives — one person split into several |
| Loose | Few false negatives, more false positives — different people merged |

There is no setting with neither. The right place to sit depends on the cost of each
mistake: if the next step is counting distinct authors, merging two people changes a count
by one in the other direction from splitting one.

> Every name-matching rule makes mistakes. Pick the direction of the mistakes deliberately.
