Before any model, chart or correlation, somebody has to get the data and make it usable.
That work is called **data munging** or **data wrangling**: *the art of acquiring data and
preparing it for analysis.*

The lecture opens with a joke that is also a measurement. Good data scientists spend most of
their time cleaning and formatting data. The rest spend most of their time complaining that
there is no data available. Both halves point at the same fact: **the data is rarely handed to
you in a usable state, or at all.**

## Tools

No single language does everything, and the lecture lists what each is known for:

| Tool | What it is good at |
| --- | --- |
| Python | Libraries and features, such as regular expressions, that make munging easier |
| R | The statisticians' language |
| Matlab | Fast, efficient matrix operations |
| Java / C | Big Data systems |
| Mathematica / Wolfram Alpha | Symbolic maths |
| Excel | The bread-and-butter tool for exploration |

The course leans on Python, but the table is the useful part: choose by what the job needs,
not by habit. Excel is on the list on purpose — for a first look at a small table it is often
the fastest thing there is.

## What this week covers

The rest of the week follows the work in order: where to **find** data, how to spot when
processing has **damaged** it, how to make data from different places **compatible**, and what
to do about **missing** values and **outliers**.

> Wrangling is not preparation for the real work. It is a large part of the real work, and
> the quality of every later result depends on it.
