Week 10 predicted a number: a house price, a profit. This week the answer is a category. Is
this email spam? Is this transaction fraudulent? Is this tumour malignant? Each has two
possible answers, so the label `y` is either 0 or 1.

| value | name | example |
| --- | --- | --- |
| `y = 0` | negative class | benign tumour |
| `y = 1` | positive class | malignant tumour |

"Positive" means "the thing we are looking for is present". It is not a judgement about
whether that is good news.

## Trying linear regression anyway

Slide 3 plots tumour size against the label. The benign tumours sit on the bottom line at 0
and the malignant ones on the top line at 1. You already know how to fit a line `hθ(x) = θᵀx`
through points, so fit one and add a rule:

- if `hθ(x) ≥ 0.5`, predict `y = 1`
- if `hθ(x) < 0.5`, predict `y = 0`

On the first eight points this works. The line crosses 0.5 somewhere between the two groups.

Now add the ninth point on the slide: one very large malignant tumour far to the right. It is
an easy case. But least squares wants the line close to *every* point, so the line tilts
flatter to reach it. The crossing at 0.5 slides to the right, and malignant tumours that were
correctly flagged now sit below the threshold.

An example that should have changed nothing made the classifier worse.

## The second problem

A straight line keeps going. For a large enough tumour `hθ(x)` is above 1, and for a small
enough one it is below 0. Slide 4 states this directly: the labels are 0 or 1, yet `hθ(x)`
can be `> 1` or `< 0`. An output of 1.4 has no sensible reading when the only answers are 0
and 1.

**Logistic regression** fixes this by guaranteeing `0 ≤ hθ(x) ≤ 1`. Despite its name it is a
classification method. The "regression" is historical.

> Classification predicts a category, not a quantity. A thresholded straight line is the
> wrong tool: easy far-away examples drag it around, and its outputs escape the range 0 to 1.
