Prim's algorithm grows **one tree** outward from a starting vertex. At every step it takes
the cheapest edge that reaches a vertex the tree does not have yet.

## The rule

**Initialise.** Choose any start vertex `s`. The set of reached vertices is `X = {s}`, and
the tree has no edges.

**Repeat until `X = V`.**

1. Look at every edge `(u, v)` with `u ∈ X` and `v ∉ X`, that is, one end in the tree and
   one end outside it.
2. Take the one of smallest weight.
3. Add `v` to `X` and add `(u, v)` to the tree.

**Result.** The chosen edges form a minimum spanning tree.

Each step adds one vertex and one edge, so after `n − 1` steps every vertex is in and there
are `n − 1` edges. That is the count Fact 1 said a spanning tree has.

## Worked: the four towns, starting from `b`

The edges are `(a, b)` 1, `(b, d)` 2, `(a, d)` 3, `(a, c)` 4 and `(c, d)` 5.

| Step | `X` before | Edges with one end in `X` | Take |
| --- | --- | --- | --- |
| 1 | `{b}` | `(a, b)` 1, `(b, d)` 2 | `(a, b)` 1 |
| 2 | `{a, b}` | `(a, c)` 4, `(a, d)` 3, `(b, d)` 2 | `(b, d)` 2 |
| 3 | `{a, b, d}` | `(a, c)` 4, `(c, d)` 5 | `(a, c)` 4 |

Three edges for four vertices, total `1 + 2 + 4 = 7`. This matches the answer to the opening
puzzle.

Look at step 2. `(b, d)` was available in step 1 too, and lost to `(a, b)`. It is chosen in
step 2 because it is still the cheapest edge leaving the tree. The list of candidates
**changes** as `X` grows: new edges appear when a vertex joins, and edges with both ends in
`X` drop out.

## What "greedy" means here

Each step makes the locally best choice, the cheapest way to reach one more vertex, and never
reconsiders it. That is the pattern that lost with coins. Here it is correct, and the cut
property later in the week explains why. For now, notice what Prim *never* considers: an edge
between two vertices already in `X`. Such an edge would close a cycle, and because Prim only
takes edges that reach a new vertex, it cannot make that mistake.

A different start vertex can change the order in which edges are added. If several MSTs
exist, it can also change which tree is returned. The total weight is always the same.

> Prim keeps one connected tree and repeatedly takes the cheapest edge out of it. Every edge
> it takes reaches a new vertex, so it never closes a cycle.
