`O(nW)` has two letters multiplied together and no exponent in sight. It looks polynomial.
It is not, and the reason is the idea week 2 was built on: **input size is how much you have
to type, not the value of what you typed**.

Polynomial means that typing a little more input makes the work grow only a little. Keep the
same four items and change nothing but `W`:

| `W` you type | Extra characters | Table cells (`4 × W`) |
| --- | --- | --- |
| 10 | — | 40 |
| 10,000 | 3 zeros | 40,000 |
| 10,000,000 | 3 more zeros | 40,000,000 |

Every three extra keystrokes multiply the work by 1,000. That happens because the table has
one column per pound of capacity, so it is as wide as the *value* of `W`.

## In general

If `W` has `d` digits then `W` is about `10ᵈ`. So `O(nW)` is really

```
O(n · 10ᵈ)
```

which is exponential in `d`. It is not `d²` or `d³` or any fixed power of `d`. An algorithm
like this, polynomial in a number's value and exponential in its length, is called
**pseudo-polynomial**.

## Why sorting is different

Sorting also takes numbers as input, but 37 and 37,000,000 each cost it one comparison. Its
work follows *how many* numbers you give it, so making the numbers themselves larger changes
almost nothing. The knapsack table's work follows *how big* one of the numbers is.

Counting sort, at `O(n + k)` for keys up to `k`, is pseudo-polynomial for the same reason
as the knapsack: it builds an array as long as the largest key.

## Why it matters

The knapsack problem is NP-hard: nobody knows an algorithm that is fast on every input. If
`O(nW)` were truly polynomial, this table would be such an algorithm, and one of the central
open questions of the field would have been settled by a ten-line loop. It has not been.
The table is fast only when `W` is small.

That is still useful. A bag measured in whole pounds, or a budget in whole dollars, often
has a small `W`. But change the units from kilograms to milligrams and the same problem
needs a table a million times wider, although nothing about the burglar's situation has
changed.

> Before calling a running time polynomial, ask what each letter measures. A letter that
> stands for the value of an input number hides an exponential in the number of digits.
