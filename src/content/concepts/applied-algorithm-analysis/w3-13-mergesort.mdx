Mergesort is the divide-and-conquer paradigm applied to sorting, and it is almost
embarrassingly direct:

1. **Divide** the array in half.
2. **Conquer** — sort each half recursively.
3. **Combine** — merge the two sorted halves.

```
function mergesort(a[1…n])
  Input:  An array of numbers a[1…n]
  Output: A sorted version of this array

  if n > 1:
    return merge( mergesort(a[1…⌊n/2⌋]), mergesort(a[⌊n/2⌋+1…n]) )
  else:
    return a
```

## Splitting is free

Worth stating plainly, because it is what makes the analysis simple: **splitting the array
costs nothing.** It is index arithmetic — naming two ranges — with no comparisons and no
copying.

Follow the eight numbers on slide 32 down the divide phase and nothing happens to them. They
are cut, then cut again, until each sits alone. A single element is already sorted, so the
base case does nothing either.

> All of the real work happens inside `merge`, on the way back **up**.

That is the opposite of the quadratic sorts from the previous page, which do their work on
the way *through*. Here the descent is pure bookkeeping and the ascent is where every
comparison lives.

## What this buys, in advance

Two recursive calls on half the array, plus a merge:

```
T(n) = 2T(n/2) + O(n)
```

That is exercise row (a) from the recurrences module — `a = 2`, `b = 2`, `d = 1`, so
`log₂2 = 1 = d`, the balanced case, `O(n log n)`.

element by element, and how the merges stack up across the levels.
