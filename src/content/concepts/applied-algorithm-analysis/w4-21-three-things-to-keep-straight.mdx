Three claims worth being precise about, now that all three algorithms this week share the
same underlying theorem.

**1 · The speed is not in the Fourier part.** Evaluating at `n` *arbitrary* points is still
`O(n²)`. The saving comes from choosing points that are closed under squaring, so the
subproblems share their work — a different set of `n` points, without that closure property,
would buy nothing.

**2 · Strassen and the FFT are not the same trick.** Strassen lowers `a` from 8 to 7 and moves
the exponent within the same *leaves-pay* case. The FFT changes the **problem** into one whose
recurrence is already balanced. Both are read off the same theorem, but one moves along a
case, and the other moves into a different case entirely.

**3 · `O(n^2.81)` is not the end of the story.** Strassen was 1969; the exponent has been
pushed lower since, and the current theoretical record is not practical. For matrices people
actually multiply, tuned `O(n³)` code usually wins — the same crossover caution that applied
to Karatsuba back in module 3: asymptotics tell you how cost grows, not which program to run
today.
