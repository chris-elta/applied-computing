Brackets are awkward to reason about. A picture is easier. Every way of bracketing a chain
can be drawn as a tree:

| Part of the tree | What it stands for |
| --- | --- |
| Leaves | the individual matrices, left to right |
| Interior nodes | intermediate products |
| Root | the final product: the last multiplication performed |

For four matrices there are five trees. Three of them:

```
((AB)C)D         A((BC)D)         (A(BC))D
```

In the first, the root joins `(AB)C` with `D`. In the second it joins `A` with `(BC)D`.
Reading the root tells you where the last multiplication splits the chain.

Each multiplication order is a **full binary tree** with `n` leaves: every node has 0 or 2
children, because a multiplication joins exactly two things.

## What a subtree is

Take any interior node and look at the leaves below it. They are always neighbours in the
chain: a **stretch** such as `B C D`. The subtree is one particular way of multiplying that
stretch together, and it is itself a bracketing of a shorter chain.

So the tree for the whole chain is made of trees for stretches. That suggests the
subproblems. What makes them usable is the next fact.

## Optimal substructure

**In the cheapest tree, every subtree is also the cheapest for its stretch.**

The argument is a swap. Suppose the cheapest tree for the whole chain contained a subtree
that was *not* the cheapest way to multiply its stretch. Cut it out and put the cheapest one
in its place.

- The new subtree computes the same product, so its result has the same shape.
- Everything above it in the tree multiplies by that result. Those costs depend only on
  shapes, so none of them changes.
- The subtree itself got cheaper.

The whole tree is now cheaper than before. But it was supposed to be the cheapest already.
That is a contradiction, so the supposition was wrong.

## Why this matters

Without this fact, knowing the best way to multiply `B C D` would tell you nothing about the
best way to multiply `A B C D E`: perhaps the best overall plan needs a deliberately
wasteful middle. The swap argument rules that out. The only thing the outside world sees of
a stretch is the shape of its product, and that shape is the same however the stretch was
multiplied.

Compare the knapsack. There the argument was "take the last item out and what is left must
be a best packing of the smaller bag". Same swap, different object.

> Optimal substructure is what you check before trusting a recurrence. Ask what the rest of
> the solution can see of a subproblem. If it sees only something the subproblem's
> definition already fixes, best pieces combine into a best whole.
