Now give the burglar one of each item. The table from the unlimited version breaks at
once. `K(w)` said: put an item in, then solve the same problem on a smaller bag. With one
copy each, the smaller bag does *not* face the same problem, because the item just taken is
gone. Knowing the capacity is no longer enough. The subproblem also has to say which items
are still available.

Recording an arbitrary set of remaining items would need `2ⁿ` subproblems. The fix is to
put the items in a line and only ever ask about a prefix of it.

## The three steps

Line the items up: A, B, C, D.

**Subproblem.** `K(w, j)` is the best value that fits in a bag of capacity `w` if you may
use only the first `j` items. For example `K(10, 2)` uses only A and B in a 10-pound bag,
so it is $44.

**Recurrence.** Look at item `j`, the last one allowed. Either it is left out or it is
taken:

```
K(w, j) = max{ K(w, j−1),  K(w − wⱼ, j−1) + vⱼ }
```

| Option | What remains | Value |
| --- | --- | --- |
| Leave item `j` out | same bag, first `j − 1` items | `K(w, j−1)` |
| Take item `j` | bag smaller by `wⱼ`, first `j − 1` items | `K(w − wⱼ, j−1) + vⱼ` |

If `wⱼ > w` the item does not fit and only the first option exists.

**Order.**

```
Initialize all K(0, j) = 0 and all K(w, 0) = 0
for j = 1 to n:
    for w = 1 to W:
        if w_j > w:  K(w, j) = K(w, j−1)
        else:        K(w, j) = max{ K(w, j−1),  K(w − w_j, j−1) + v_j }
return K(W, n)
```

## What the second index does

Both options read row `j − 1`, where item `j` is not allowed. That is what stops an item
from going in twice. Compare the unlimited version, where every item stayed available after
it was taken: there the "take" branch read the same one-dimensional table it was writing.
Here item `j` is used up, and reading the row above is how the table knows.

The order of the items does not matter. Any line-up gives the same final answer; the index
`j` only needs *some* fixed order so that "the first `j`" means something.

## Cost

There are `(n + 1)(W + 1)` cells and each takes a constant amount of work: two lookups, an
addition and a comparison. Time and space are both `O(nW)`, the same pseudo-polynomial
bound as before.

Swapping the two loops also works. Every cell reads two cells in the row above it, and with
either nesting those are filled first.

> When a choice uses something up, the subproblem has to record what is left. Ordering the
> choices and indexing by a prefix records it with one extra number instead of a whole set.
