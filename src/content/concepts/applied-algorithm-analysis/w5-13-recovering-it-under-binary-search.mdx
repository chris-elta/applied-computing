The binary-search method ends with `sub`, and an earlier concept showed that `sub` is not a
subsequence of the input. To rebuild a real one, use the same plan as the table method: walk
back from the last number, with each number remembering the one just before it. `sub` cannot
do that, so two more arrays are kept alongside it.

## The two arrays

**`pos[k]` — where `sub[k]` came from.** `sub[k]` holds a number from `nums`; `pos[k]` says
at which position. After reading 10, 5, 8 from `nums = [10, 5, 8, 3, 9]`: `sub = [5, 8]` and
`pos = [1, 2]`, because 5 is `nums[1]` and 8 is `nums[2]`.

**`parent[i]` — an arrow back.** Each number points to the number just before it in its
subsequence. `parent[2] = 1`: the number before 8 is 5, which is `nums[1]`.

## Filling them

When `nums[i]` lands at position `k`, the number before it is the one in `sub[k−1]`, and its
position in `nums` is `pos[k−1]`. So `parent[i] = pos[k−1]`.

```
for i = 0 … n−1:
    k = first position with sub[k] ≥ nums[i]     (k = len(sub) if none)
    parent[i] = pos[k−1] if k > 0 else −1        ← new: copy the arrow now
    sub[k] = nums[i]                             (appends when k = len(sub))
    pos[k] = i                                   ← new: remember where it came from
```

**Copy it at that moment.** Later, `sub[k−1]` may be replaced by a smaller number, but
`parent[i]` does not change.

| `i` | `nums[i]` | lands at `k` | `parent[i]` | `sub` | `pos` |
| --- | --- | --- | --- | --- | --- |
| 0 | 10 | 0 | −1 | `[10]` | `[0]` |
| 1 | 5 | 0 | −1 | `[5]` | `[1]` |
| 2 | 8 | 1 | 1 | `[5, 8]` | `[1, 2]` |
| 3 | 3 | 0 | −1 | `[3, 8]` | `[3, 2]` |
| 4 | 9 | 2 | 2 | `[3, 8, 9]` | `[3, 2, 4]` |

Row 3 is the one to study. The 3 replaces the 5, so `pos[0]` becomes 3 — but `parent[2]` was
written a row earlier and stays 1. The deck's slide 42 animates this run, and a longer one.

## Walking back

1. `sub` has 3 entries, so start at the last: `pos[2] = 4`.
2. Follow `parent`: 4 → 2 → 1 → −1. The numbers met are 9, 8, 5.
3. Reverse: `[5, 8, 9]` — a real subsequence, not `[3, 8, 9]`.

Why is it guaranteed real? Each arrow was written when `nums[i]` arrived. The number it
points to was already in `sub` then, so it is **earlier** in `nums`; and it was `sub[k−1]`,
so it is **smaller**. Along the walk, positions go left and numbers go down. Reversed, they
go right and up.

The cost is two extra arrays, `O(n)` space. The time stays `O(n log n)`.

> `sub` and `pos` describe the present and get overwritten. `parent` records the past and
> is never touched again. Reconstruction always needs something that is written once.
