Three statements that are easy to believe by the end of this week. Each has a true idea
inside it, which is what makes it tempting.

## 1 · "The answer is `dp[n−1]`."

Only when the subproblem is about the **whole prefix**. For edit distance, `E(i, j)`
compares two complete prefixes, so `E(m, n)` compares the two complete strings and is the
answer. For the LIS the state is *ending at `i`*, so each cell speaks for one ending only
and the answer is a `max` over the entire array.

There is no rule to memorise here. Read your own definition from step 1, and ask which
cell — or which combination of cells — that sentence makes into the answer.

## 2 · "Memoization and tabulation are different algorithms."

They have the same subproblems, the same recurrence and the same asymptotic cost. What
differs:

| | Differs? |
| --- | --- |
| Subproblems | no |
| Recurrence | no |
| Growth rate | no |
| Order of evaluation | yes |
| Constants | yes |
| Call-stack usage | yes |
| Whether unneeded subproblems get solved | yes |

Choosing between them is an engineering choice. If a solution is wrong, switching from one
to the other will reproduce the same wrong answer.

## 3 · "My recurrence passes the examples, so the state is right."

This is the one that costs marks. A state that does not carry enough information can still
fit small cases. The LIS is the standing example: "the best among the first `i` elements"
sounds like a subproblem, and a recurrence can be written on top of it that gets the
lecture's own example right — while having no way of knowing whether the next number may
legally be added.

The test is not more examples. It is the sentence:

- Can you say in **one English sentence** what `dp[i]` means?
- Can you **justify the transition from that sentence** — explain why each term is there?

If either answer is no, you do not have a subproblem yet, whatever the output says. Write
the sentence before the code.

> All three mistakes come from treating the table as numbers that happen to work. Every one
> of them is caught by going back to step 1 and reading what a cell means.
