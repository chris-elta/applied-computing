## BFS and DFS in one table

| | breadth-first search | depth-first search |
| --- | --- | --- |
| data structure | queue: first in, first out | recursion, or a stack: last in, first out |
| when to mark | when a vertex **joins** the queue | when its call **starts** (recursive); when first **popped** (stack) |
| traversal | by distance layers | follow a path, then go back |
| what its order gives | shortest paths in an unweighted graph; connected components | topological order in a DAG; connected components |
| running time | `O(n + m)` | `O(n + m)` |

All the time bounds assume adjacency lists and `O(1)` queue or stack operations.

## Five things to keep

**1 · A graph is two lists, and how you store them matters.** A matrix costs `Θ(n²)` cells
whatever `m` is; adjacency lists cost `Θ(m + n)` and hand over neighbors directly. Graph
search repeats "give me the neighbors", so it uses lists — and a matrix turns the same BFS
into `Θ(n²)`.

**2 · One search, one open line.** While some edge crosses from explored to unexplored, mark
its head. Whatever edge you choose, explored ends up exactly the reachable set. BFS and DFS
are two ways to choose.

**3 · BFS: queue, mark on enqueue, layers are distances.** Each reachable vertex is queued
once. BFS finishes each layer before the next, so the first label a vertex gets is its
distance in *edges* — not weight. Parent pointers recover the path in `O(n)` extra space.

**4 · Restart, keep the marks.** Starting a search at every still-unexplored vertex labels
all connected components, and because the marks persist, the whole run is still
`O(n + m)`.

**5 · DFS: go back only at a dead end, and use the finishing order.** In a stack version the
mark goes on the pop. For a DAG, numbering vertices from `n` down as their calls finish
gives a topological ordering. Marking order does not.

## Think first

Try each before reading the answer under it.

**Why does marking on enqueue prevent duplicate entries in BFS?**
Between joining the queue and leaving it, a vertex is already marked, so no other neighbor
can add it again. Mark on removal and every neighbor processed in that window adds another
copy.

**Why does BFS finish each layer before the next?**
All of layer `i` joins the queue before any of layer `i + 1`, because layer `i + 1` is only
discovered while layer `i` is being removed. A queue releases in arrival order.

**Why do all the component searches together scan each list only once?**
The marks are set once, outside the outer loop, and never reset. A vertex explored by one
search is skipped by every later one, and its list is walked by the one search that
removed it.

**Why can topological sort not use the simple vertex-stack DFS?**
It has no moment when a vertex's exploration *finishes* — no return event — and the
numbering is assigned exactly then. Recursion, or a stack of explicit call frames, provides
it.
