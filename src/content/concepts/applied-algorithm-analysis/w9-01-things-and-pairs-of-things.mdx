A friendship network, a road map, the links between web pages and a list of course
prerequisites look nothing alike. Strip each one down and the same two lists are left:

| | things | pairs of things |
| --- | --- | --- |
| friendships | people | who is friends with whom |
| road map | intersections | which intersections a road joins |
| web | pages | which page links to which |
| prerequisites | courses | which course must come before which |

That is all a **graph** is. There are no coordinates, no lengths and no picture. A drawing
is a convenience for humans; the algorithm sees only the lists. The benefit of the one name
is that an algorithm written for graphs works on all four problems, so it never has to be
invented four times.

## Writing it down

We write `G = (V, E)`. The things are **vertices**, collected in the set `V`. The pairs are
**edges**, collected in `E`.

Graphs come in two flavours, and the notation records which one you have:

| | undirected | directed |
| --- | --- | --- |
| edge written | `{v, w}` — braces | `(v, w)` — round brackets |
| order matters? | no: `{v, w} = {w, v}` | yes: runs from tail `v` to head `w` |
| can be followed | either way | tail to head only |
| example | friendship | a web link, a one-way street, a prerequisite |

The bracket shapes are the whole difference on paper, and they are easy to misread. Braces
are set notation, and a set has no order. Round brackets make an ordered pair, and swapping
the entries gives a different pair.

## Why direction changes the answers

Take the four vertices `s, v, w, t` from the slide, joined by five edges. In the undirected
version, every vertex can get to every other: the graph is in one piece. Put arrows on the
same five edges and that stops being true. A vertex whose edges all point away from it can
leave but cannot be reached from anywhere else.

So the question *which vertices can I get to from here?* has different answers on the two
graphs, even though they have the same drawing without arrows. That question, called
**reachability**, drives the rest of the week: breadth-first search, depth-first search,
connected components and topological ordering are all answers to it, or to a refinement of
it.

> A graph is two lists: things, and pairs of things. Whether the pairs are ordered —
> `(v, w)` against `{v, w}` — changes which vertices can reach which, and so it changes
> what every algorithm this week returns.
