The table holds a cost in every cell and nothing else. The bottom-right cell says the edit
distance between SNOWY and SUNNY is 3; it does not say which three edits. The LIS table had
the same gap and filled it with a `prev` array. Here there is a way that needs no extra
storage at all.

## Ask each cell where its value came from

Start at the bottom-right cell. Its value was the smallest of three candidates, one per
scenario. Recompute the three and see which one equals the value: that scenario is the
**last column** of the alignment, and it says which cell to visit next.

| Cell | Value comes from | Column |
| --- | --- | --- |
| `(5, 5)` | Scenario 3: `0 + E(4, 4) = 3` | `Y / Y` |
| `(4, 4)` | Scenario 3: `1 + E(3, 3) = 3` | `W / N` |
| `(3, 3)` | Scenario 3: `1 + E(2, 2) = 2` | `O / N` |
| `(2, 2)` | Scenario 3: `1 + E(1, 1) = 1` | `N / U` |
| `(1, 1)` | Scenario 3: `0 + E(0, 0) = 0` | `S / S` |

Read the columns in reverse: `S N O W Y` over `S U N N Y` — three substitutions, cost 3.

At `(4, 4)` scenario 1 also gives 3. Taking it leads to the alignment with gaps from the
alignments concept. Both are best; as with the LIS, the answer is not unique.

## The code

```
i = m; j = n
while i > 0 or j > 0:
    if i > 0 and j > 0 and E(i, j) = diff(i, j) + E(i−1, j−1):     Scenario 3
        add column (x[i], y[j]); i = i − 1; j = j − 1
    else if i > 0 and E(i, j) = 1 + E(i−1, j):                     Scenario 1
        add column (x[i], −); i = i − 1
    else:                                                          Scenario 2
        add column (−, y[j]); j = j − 1
reverse the list of columns
```

Four things to take from it:

- **Why `or`.** When one string runs out first, the other still has letters that need
  columns. With `and`, CAT against AT would stop early and lose the column `C / −`.
- **Cost.** Each step lowers `i` or `j` or both, so the walk takes at most `m + n` steps:
  `O(m + n)`, small beside the `O(mn)` spent filling the table.
- **Memory.** The three scenarios are re-checked at each cell, so nothing extra is stored.
  But this needs the **whole table** — the two-row saving from the previous concept is not
  available.
- **Same idea.** For the LIS, `prev[i]` recorded which earlier number won. Here the table
  itself lets you work out who won.

## Practice

LeetCode 62 (*Unique Paths*), 63 (*Unique Paths II*) and 120 (*Triangle*) are all the same
grid with a different operation in the cell: the recurrence changes and the table shape does
not.

> Filling a table answers "how much?". Walking back through it answers "how?". The walk is
> cheap, but only if you kept what it needs to read.
