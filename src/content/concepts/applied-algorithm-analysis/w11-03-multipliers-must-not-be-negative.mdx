The multipliers 0, 5 and 1 were a guess that worked. To search for multipliers on purpose,
give each constraint an unknown one:

| multiplier | constraint |
| --- | --- |
| `y₁` | `x₁ ≤ 200` |
| `y₂` | `x₂ ≤ 300` |
| `y₃` | `x₁ + x₂ ≤ 400` |

The guess is the particular choice `(y₁, y₂, y₃) = (0, 5, 1)`. What must *any* choice
satisfy for the argument to go through? There are three requirements. This is the first.

## Multiplying an inequality

Take a true statement, `3 ≤ 5`.

| multiply both sides by | result | still true with `≤`? |
| --- | --- | --- |
| 2 | `6 ≤ 10` | yes |
| 0 | `0 ≤ 0` | yes |
| −1 | `−3 ≤ −5` | **no**. The true statement is `−3 ≥ −5` |

Multiplying by a negative number flips the order. So a negative multiplier turns a `≤`
constraint into a `≥` statement, and a `≥` statement cannot be added into a sum of `≤`
statements.

On the bakery: the plan with `x₁ = 50` satisfies `x₁ ≤ 200`. Multiply by −1 and keep the
`≤`, and you would be claiming `−50 ≤ −200`, which is false.

## Requirement 1

To keep the direction of all three `≤` inequalities when multiplying:

```
y₁, y₂, y₃ ≥ 0
```

With that, each weighted constraint is true of every feasible plan:

```
y₁·x₁          ≤ 200y₁
y₂·x₂          ≤ 300y₂
y₃·(x₁ + x₂)   ≤ 400y₃
```

and so is their sum. Zero is allowed. A multiplier of 0 turns its line into `0 ≤ 0`, which
is true and contributes nothing, so that constraint is not used. The guess `(0, 5, 1)` did
exactly that with the first constraint.

## What goes wrong without it

The damage is not a weaker bound. It is a **false** one. A negative multiplier can produce a
number below what a real plan earns, which is then not a bound at all. The knowledge check
below works one such case through.

Notice also what this requirement depends on: every constraint here is a `≤`. For a
constraint written with `=` or `≥`, the allowed sign of its multiplier is different. That is
the subject of the transformation rules later this week.

> A multiplier on a `≤` constraint must be non-negative, because a negative number reverses
> the inequality and the weighted lines could no longer be added.
