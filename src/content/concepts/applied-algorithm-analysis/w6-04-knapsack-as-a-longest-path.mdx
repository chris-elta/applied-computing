Week 5 ended its treatment of dags with a claim: every dynamic program is a dag, with
subproblems as vertices and dependencies as edges. The knapsack with repetition is a clean
place to check that, because its dag can be drawn in full.

## Building the graph

- Each capacity `0, 1, …, W` is a vertex.
- For each item `i` and each capacity `w ≥ wᵢ`, draw an edge from `w − wᵢ` to `w`, labelled
  with the value `vᵢ`. Following that edge means "add one copy of item `i`".
- Every weight is a positive whole number, so every edge points to a strictly larger
  capacity. You can never come back to where you were. There are no cycles: it is a dag.

A path from 0 is then a sequence of items going into the bag, and the labels along it add
up to the value of that packing. The best packing is the path with the largest total.

**Knapsack with repetition is the longest path in this dag.** Week 5 found the shortest
path in a dag with one pass in linearized order. Use `max` instead of `min` and the
algorithm is the same.

## A small example

Capacity `W = 6`. Item 1 weighs 2 and is worth 3. Item 2 weighs 3 and is worth 4.

Item 1 gives the edges `0→2`, `1→3`, `2→4`, `3→5`, `4→6`, each labelled +3. Item 2 gives
`0→3`, `1→4`, `2→5`, `3→6`, each labelled +4. Two of the routes that arrive at 6:

| Route | Items | Total |
| --- | --- | --- |
| `0 → 3 → 6` | two of item 2 | 4 + 4 = 8 |
| `0 → 2 → 4 → 6` | three of item 1 | 3 + 3 + 3 = 9 |

The longest path wins, and it uses only item 1, although item 2 is worth more per copy.
Three cheap steps beat two dear ones. Counting edges also explains the cost: 5 + 4 = 9 of
them here, at most `n × W` in general, and the algorithm looks at each once.

## What the picture is for

The recurrence for `K(w)` and the dag algorithm are the same computation. `K(w)` takes a
`max` over items; the dag algorithm takes a `max` over incoming edges; and there is one
incoming edge per item that fits. Seeing the graph tells you why filling `w = 1, 2, …, W`
is a legal order: it is a linearization, with every arrow pointing rightwards.

## Practice

LeetCode 322 (Coin Change), 518 (Coin Change II) and 279 (Perfect Squares) are all
knapsacks with repetition: coins are reusable items and the amount is the capacity. In 518,
which counts the ways to make an amount, the loop order matters. Put the coins in the outer
loop and the amounts inside. The other order counts `1 + 2` and `2 + 1` separately, giving
permutations instead of combinations. Run it both ways and watch the answer change.

> If you can draw the subproblems as a dag, you already have the algorithm: one pass in an
> order that follows the arrows. Changing the problem often changes only the graph.
