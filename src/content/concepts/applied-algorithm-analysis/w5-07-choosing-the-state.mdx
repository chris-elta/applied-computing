Ask a room for a subproblem and most people offer "the length of the LIS among the first `i`
elements". It sounds right, and it is the definition that makes the answer sit neatly in the
last cell. It also does not work, and seeing why is the most useful thing in this module.

## What the state has to carry

Say you know the longest increasing subsequence among the first five numbers has length 3,
and the sixth number is 7. Can you extend it to length 4?

It depends on whether that subsequence ends in something smaller than 7. And the state does
not say. A length alone is not enough information to take the next step.

The fix is to put the missing information into the definition:

> `dp[i]` = the length of the longest increasing subsequence **ending at index `i`**.

Now the last number is known — it is `nums[i]` — and the question "can I extend this?" has
an answer.

## Step 2 — the transition

A subsequence ending at `i` is `nums[i]` on its own, or `nums[i]` added to some increasing
subsequence that ends earlier with a smaller number. Take the longest of those:

```
dp[i] = 1 + max{ dp[j] : j < i, nums[j] < nums[i] }
```

If no such `j` exists, `dp[i] = 1`.

This is the longest-path sweep from the previous concept, written down: the edges into node
`i` come from every earlier `j` with a smaller number, and `max` replaces `min`.

## Step 3 — initialize, then read the answer

Start with `dp[i] = 1` for every `i`: each element alone is an increasing subsequence of
length 1. Fill left to right.

Then:

```
LIS = max{ dp[0], dp[1], …, dp[n−1] }
```

**The answer is not `dp[n−1]`.** That cell is about subsequences ending at the last element,
and the best one need not end there. Why? Because of the definition you chose. You bought
the ability to write a recurrence by making each cell about one particular ending, and the
price is that no single cell is about the whole array.

> A state has to carry enough information to take the next step. When it does, check what
> each cell now means before deciding where the answer is.
