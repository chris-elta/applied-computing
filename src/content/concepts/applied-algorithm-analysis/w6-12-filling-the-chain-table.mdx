Four matrices: `A` is `50 × 20`, `B` is `20 × 1`, `C` is `1 × 10`, `D` is `10 × 100`. So
the input is `m = 50, 20, 1, 10, 100`.

A stretch needs `i ≤ j`, so only the upper triangle of the table exists:

| `i \ j` | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- |
| **1** | 0 | 1,000 | 1,500 | 7,000 |
| **2** | | 0 | 200 | 3,000 |
| **3** | | | 0 | 1,000 |
| **4** | | | | 0 |

## Reading it

The diagonal is the base case: one matrix, no multiplication, cost 0.

The next diagonal holds the pairs. Each has a single split, so it is one `pqr` product:

| Cell | Stretch | Cost |
| --- | --- | --- |
| `C(1, 2)` | `AB` | `50·20·1 = 1,000` |
| `C(2, 3)` | `BC` | `20·1·10 = 200` |
| `C(3, 4)` | `CD` | `1·10·100 = 1,000` |

## One cell in full

`C(1, 3)` is the stretch `A B C`. The last multiplication can split it in two places.

```
k = 1:  C(1,1) + C(2,3) + 50·20·10  =  0 + 200 + 10,000  =  10,200      A(BC)
k = 2:  C(1,2) + C(3,3) + 50·1·10   =  1,000 + 0 + 500   =   1,500      (AB)C
```

`C(1, 3) = 1,500`. These are the same two totals as in the earlier comparison of `(AB)C`
with `A(BC)`. There they were worked out by hand; here each is two lookups, one product
and two additions.

Look at which cells were read: `C(1,1)`, `C(2,3)`, `C(1,2)`, `C(3,3)`. Every one is a
shorter stretch than `A B C`. That matters for the order of filling, which the next concept
takes up.

## The corner

`C(1, 4)` has three splits:

```
k = 1:  C(1,1) + C(2,4) + 50·20·100  =  0 + 3,000 + 100,000  =  103,000   A(BCD)
k = 2:  C(1,2) + C(3,4) + 50·1·100   =  1,000 + 1,000 + 5,000 =    7,000   (AB)(CD)
k = 3:  C(1,3) + C(4,4) + 50·10·100  =  1,500 + 0 + 50,000   =   51,500   (ABC)D
```

`C(1, 4) = 7,000`, at `k = 2`: the plan is `(AB)(CD)`.

The split through the middle wins because `m₂ = 1`. Both halves collapse onto that
dimension, so the final multiplication is a `50 × 1` matrix times a `1 × 100` matrix.

For scale, the worst of the five bracketings, `A((BC)D)`, costs 120,200. That is 17 times
the best, for the same result.

## What the table saved

`C(2, 3) = 200` was computed once and then read twice: by `C(1, 3)` and by `C(2, 4)`. In a
longer chain a stretch like `BC` sits inside a great many different trees, and each of them
would otherwise cost it out again.

> A cell in this table is a `min` over splits, and every split reads two cells for shorter
> stretches. If you can work one cell by hand, you know the whole algorithm.
