  - symbol: "nⁿ"

    means: >-

`n!` is every whole number from 1 to `n` multiplied together. It gets huge fast:
`10! = 3,628,800`. There is no tidy formula for it, so how fast does its logarithm grow?

```
log(n!) = log 1 + log 2 + log 3 + … + log n
```

The log turns the product into a sum, which is why the question is asked about `log(n!)`
rather than `n!` itself. The answer is `Θ(n log n)`, and the proof needs no formula. You
**trap** `n!` between two simple powers, one above and one below.

## Above: make every factor the biggest

`n!` has `n` factors and none is bigger than `n`. Replace every one with `n` and the product
can only grow:

```
n! = 1 · 2 · 3 · … · n  ≤  n · n · n · … · n  =  nⁿ
```

Bigger numbers have bigger logs, so take logs of both sides and bring the exponent down:

```
log(n!) ≤ log(nⁿ) = n log n
```

That is `O(n log n)`.

## Below: drop the small half, shrink the rest

A lower bound needs something that is **never bigger** than `n!`. Two moves, both pushing
the product down:

1. **Throw away the smaller half of the factors.** Each is at least 1, so removing it can
   only shrink the product.
2. **Replace each factor you kept with `n/2`.** Every kept factor is at least `n/2`, so this
   shrinks it again.

With `n = 8`:

```
8! = 1 · 2 · 3 · 4 · 5 · 6 · 7 · 8  ≥  5 · 6 · 7 · 8  ≥  4 · 4 · 4 · 4  =  4⁴
```

In general `n! ≥ (n/2)^(n/2)`. When `n` is odd, round the number of kept factors down to
`⌊n/2⌋`. Taking logs:

```
log(n!) ≥ (n/2) · log(n/2) = (n/2)(log n − log 2)
```

The `− log 2` looks like it could spoil things, but it is a constant, while `log n` keeps
growing. In base 2, once `n ≥ 4` you have `log₂ n − 1 ≥ ½ log₂ n` and `⌊n/2⌋ ≥ n/4`, so
the bound is at least `⅛ n log₂ n`. A fixed fraction of `n log n` is exactly what
`Ω(n log n)` asks for.

## The trap, closed

| `n = 8`, base 2 | value |
| --- | --- |
| lower, `(n/2) log₂(n/2)` | `4 · 2 = 8` |
| actual, `log₂ 40,320` | `≈ 15.3` |
| upper, `n log₂ n` | `8 · 3 = 24` |

Both walls are constant multiples of `n log n`, so `log(n!) = Θ(n log n)`. This is the
`Θ` recipe from the worked examples, with one change: the thing being trapped is a product,
and a log turns each wall into something you can compare.

## Why it matters

`n` items can be arranged in `n!` orders. A sort that only compares items must be able to
tell all of those orders apart, and each comparison is a yes/no answer. So its decisions form
a binary tree with at least `n!` leaves, and that tree is at least `log₂(n!)` deep. By this
page, that is `Θ(n log n)` comparisons. Mergesort, in week 3, runs in exactly that time.

> **You do not need a formula for something to bound it.** Make it bigger in a way you can
> compute, make it smaller in a way you can compute, and check that the two walls grow at the
> same rate.
