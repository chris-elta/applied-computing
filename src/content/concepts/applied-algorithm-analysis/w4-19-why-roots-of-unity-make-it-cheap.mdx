      - text: >-

      A(omega^k) = A_even(omega^{2k}) + omega^k * A_odd(omega^{2k}).
      As k ranges 0..n-1, omega^{2k} ranges over the (n/2)-th roots of unity, each value hit
      by exactly 2 values of k (k and k+n/2 give the same omega^{2k}, by the squaring

      So A_even and A_odd each only need to be evaluated at n/2 distinct points to answer all

      - text: >-
          From recomputing `A_even` and `A_odd` from scratch for each `k`
        explains: >-

---

Evaluate `A` at the `n`-th roots of unity, all `n` of them. For each `ωᵏ`:

```
A(ωᵏ) = A_even(ω^{2k}) + ωᵏ A_odd(ω^{2k})
```

As `k` runs over `0, …, n−1`, the value `ω^{2k}` runs over the `(n/2)`-th roots of unity —
**each one twice**. So the two half-size polynomials only ever need to be evaluated at `n/2`
points, not `n`. Combining the two answers takes one multiplication and one addition per `k`:
`O(n)` in total.

Two subproblems of half the size, linear combining. This is mergesort's recurrence, on
polynomials.

One practical point worth flagging before implementing it: the halving only closes cleanly if
`n` is a power of two, so an implementation pads the coefficient list with zeros up to the
next one first. Padding changes no coefficient and costs `O(n)`.
