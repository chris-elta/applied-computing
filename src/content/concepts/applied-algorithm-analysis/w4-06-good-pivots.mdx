## The ideal case

If a pivot always split `S` into two halves of roughly equal size, `∣S_L∣, ∣S_R∣ ≈ ∣S∣/2`, the
recurrence would be

```
T(n) = T(n/2) + O(n)
```

Master theorem: `a=1, b=2, d=1`, and `log₂1 = 0 < 1` — the first case, the root pays,
`T(n) = O(n)`. The recursion's own levels only add a constant factor: `n + n/2 + n/4 + ⋯ = 2n`.

## The worst case

In the worst case, the pivot is always the largest or smallest element of the array, and each
split removes exactly one element:

```
n + (n−1) + (n−2) + ⋯ + 1 = n(n+1)/2 = Θ(n²)
```

Both the ideal case and the worst case are rare. So the real question, in the spectrum from
`O(n)` to `O(n²)`, is: **what is the average running time?**

## Defining a good pivot

Call `v` **good** if it lies within the 25th to 75th percentile of the array it's chosen from.
A good `v` guarantees `∣S_L∣` and `∣S_R∣` are each at most **¾ the size of `S`** — nowhere near
the ideal half, but enough to guarantee real shrinkage every time.

Good values are plentiful for a structural reason, not a lucky one: half the elements of *any*
list fall between the 25th and 75th percentile, because percentile is a statement about
position in sorted order, not about the values themselves. Pick any element of the middle
half and both `S_L` and `S_R` come out at most ¾ of `S`. So a uniformly random pivot is good
with probability exactly **½**, whatever the list looks like.
