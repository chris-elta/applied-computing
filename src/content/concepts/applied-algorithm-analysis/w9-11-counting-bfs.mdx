How long does BFS take? Count how many times each line runs, and why.

Name the part of the graph the search can actually reach: **`nₛ`** vertices and **`mₛ`**
edges. On the six-vertex example, everything is reachable, so `nₛ = 6` and `mₛ = 8`.

| code | runs | why |
| --- | --- | --- |
| line 1: set every mark | `n` times | one mark for every vertex in the graph |
| line 4: remove a vertex | `nₛ` times | each reachable vertex joins the queue once, because it is marked on joining |
| line 5: scan a neighbor | at most `2mₛ` times | an undirected edge is in two lists, so it is scanned twice; a directed edge, once |

The `2mₛ` row is the one that needs thought. Line 5 runs once for every entry in
`Adj[v]`, for every `v` removed. Each vertex is removed once, so each list is walked once,
and the lists together hold `2mₛ` entries. In the example: 6 removals and 16 scans.

Since `nₛ ≤ n`, `mₛ ≤ m` and queue operations are `O(1)`, the total is

```
O(m + n)
```

— linear in the size of the graph. Every search algorithm this week is counted the same
way, so this one is worth doing slowly once.

## Where each letter comes from

- The **`n`** comes from initialisation: every vertex gets a mark, reachable or not.
- The **`m`** comes from line 5: each list is walked exactly once.

There is no `n · m` term, because the loop on line 5 does not run "for every vertex, over
every edge". It runs over *one vertex's* list, and each list is visited only once in the
whole search.

## With an adjacency matrix

Change only the representation. Line 5 now has to find `v`'s neighbors by reading row `v`
of the matrix — all `n` cells, 1s and 0s alike. For each reachable vertex that costs `n`:

| | per reachable vertex | example |
| --- | --- | --- |
| lists | `deg(v)` | 16 scans in total |
| matrix | `n` | 6 rows of 6 cells, 36 reads |

When every vertex is reachable the matrix version costs **`Θ(n²)`** — even on a sparse
graph, where nearly every cell read is a 0. (Exactly, it is `Θ(n + n · nₛ)`.)

This is the "list a vertex's neighbors" row of the representation table, made concrete:
the algorithm is identical, and the storage alone moves it from linear to quadratic.

> BFS with adjacency lists costs `O(m + n)`: each vertex is queued once and each list is
> walked once. With a matrix, each vertex costs a full row, and the same search is `Θ(n²)`.
