Three limits, and each one bites somewhere different.

## 1 · It does not apply to every recurrence

The theorem needs the form `aT(n/b) + O(nᵈ)`. Plenty of real recurrences are not that shape:

- `T(n) = T(n−1) + O(n)` shrinks by **subtraction**, so there is no `b` at all.
- `T(n) = T(n/3) + T(2n/3) + O(n)` splits **unequally**, so there is no single `n/b`.

Neither can be fed to the formula. Draw the recursion tree instead — which is why module 02
taught the tree before the theorem rather than after it.

> This is the one that costs marks in an exam: **check the form before reaching for the
> formula.**

## 2 · A smaller exponent is not automatically a faster program

Karatsuba buys `O(n^1.59)` against `O(n²)` — but it buys it with real extra work per bit:
splitting the input, three recursive calls rather than one flat loop, then shifting and
subtracting on the way back up.

Big-O hides that multiplier entirely. Below a few hundred bits it outweighs the better
exponent, which is why production libraries never recurse all the way down. GMP, the standard
big-number library, multiplies small inputs the schoolbook way.

The numbers, if you want them: at 64 bits schoolbook does about 4,100 operations against
Karatsuba's 8,700, and the two curves do not cross until roughly 512 bits.

> This is week 1's third misconception — *constants vanish only in the limit* — showing up
> with a concrete price tag.

## 3 · More subproblems is not the same as more work

What picks the case is `a/bᵈ`, never `a` on its own.

- Binary search: `a = 1` → balanced.
- Mergesort and exercise row (a): `a = 2` → balanced.
- Karatsuba: `a = 3` → leaves dominate, because 3 exceeds `bᵈ = 2`.

One, two and three subproblems, and the *middle* two land in the same case. The count only
means something once you weigh it against how much smaller the subproblems got and how
expensive the combine step is.
