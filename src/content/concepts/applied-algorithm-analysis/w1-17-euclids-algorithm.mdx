The **greatest common divisor** is the largest whole number dividing both inputs exactly.
("`d` divides `a`" means `a` is a whole number of `d`s: 3 divides 12, 5 does not.)

```
divisors of 12:  1, 2, 3, 4, 6, 12
divisors of 18:  1, 2, 3, 6, 9, 18
in common:       1, 2, 3, 6      →  gcd = 6
```

Now scale that to two 100-digit numbers. You cannot — you would have to factorise them, and
nobody knows how to do that quickly. A different idea is needed.

## Euclid's rule

> For `a ≥ b > 0`:  `gcd(a, b) = gcd(b, a mod b)`

`gcd(1035, 759)` becomes `gcd(759, 276)`. Smaller numbers, same answer. Repeat until
something hits zero. That is the algorithm; the interesting part is why the rule holds.

## Why it holds — a technique worth stealing

Instead of reasoning about the *greatest* divisor, show the two pairs have **the same set**
of common divisors. Identical sets, identical largest member.

Write `a = qb + r`, where `r = a mod b`. Take any `d`:

- **`d` divides `a` and `b`** → it divides `qb`, so it divides `a − qb = r`. So `d` divides
  `b` and `r`.
- **`d` divides `b` and `r`** → it divides `qb + r = a`. So `d` divides `a` and `b`.

Same set, same greatest member. ∎

> The proof never mentions "greatest" until the last sentence. Turning a question about a
> maximum into one about a whole set is worth remembering.

## The algorithm

```
function Euclid(a, b)
  if b = 0: return a
  return Euclid(b, a mod b)
```

It stops because `b` strictly decreases and cannot go below 0.

## Terminating is not the same as being fast

Decreasing by 1 each time would also terminate — after `b` steps, hopeless for a 100-digit
number. We need a **rate**:

> **Lemma.** If `a ≥ b` then `a mod b < a/2`.

Two cases. If `b ≤ a/2`: the remainder is smaller than `b`, which is already at most `a/2`.
If `b > a/2`: then `b` goes into `a` once, so `a mod b = a − b`, and since `b` is more than
half of `a`, what remains is less than half.

Either way the larger value **halves every two rounds**. An `n`-bit number halves only `n`
times, so at most `2n` rounds.

## The cost

> `2n` rounds × `O(n²)` per division = **`O(n³)`**

The worst case is consecutive Fibonacci numbers — try 610 and 377 in the slide's runner and
watch it grind one round per number. That is no coincidence: numbers whose ratio is closest
to `φ` resist division hardest. A pleasing place to end the week we began with `fib1`.
