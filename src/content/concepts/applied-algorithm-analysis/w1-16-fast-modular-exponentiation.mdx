Compute `xʸ mod N` for enormous `x`, `y`, `N`. This is the operation at the heart of RSA and
Diffie–Hellman.

## Why the obvious method fails

Reducing after every step keeps every *value* small. So multiply `x` by itself, reducing each
time. Where is the catch?

**The number of operations.** That does `y − 1` multiplications, and `y` has hundreds of
digits — something like `2⁵⁰⁰` multiplications.

Note which problem this is: the values are under control, the **count** is not. Fixing counts
is what algorithms are for.

## Halve the exponent instead of decrementing it

Decrementing `y` takes `y` steps; halving takes `log₂ y` steps — which is just `n`, the bit
length. The trick is that squaring **doubles** an exponent:

```
x¹⁶ = (((x²)²)²)²
```

Four squarings, not fifteen multiplications: 2 → 4 → 8 → 16.

```
function modexp(x, y, N)
  if y = 0: return 1
  if y is even:
    z = modexp(x, y/2, N)
    return z·z mod N
  else:
    z = modexp(x, y−1, N)
    return x·z mod N
```

Even `y`: halve, then square. Odd `y`: peel off one `x`, leaving an even exponent. And reduce
mod `N` every step.

## Watch it run — `3¹³ mod 7`

The recursion descends `13 → 12 → 6 → 3 → 2 → 1 → 0`, then fills in coming back up:

| value | how | mod 7 |
| --- | --- | --- |
| `3¹` | `3 · 3⁰ = 3` | 3 |
| `3²` | `(3¹)² = 9` | 2 |
| `3³` | `3 · 3² = 6` | 6 |
| `3⁶` | `(3³)² = 36` | 1 |
| `3¹²` | `(3⁶)² = 1` | 1 |
| `3¹³` | `3 · 3¹² = 3` | **3** |

Six rows, and nothing exceeds 36 — while `3¹³` computed directly is `1,594,323`.

## The cost

**Rounds:** the exponent at least halves per call, so at most `n` calls.
**Per round:** one modular multiplication, priced last page at `O(n²)`.

> `n` calls × `O(n²)` = **`O(n³)`**

The naive method was `y` multiplications; this is `log₂ y`. Since `y ≈ 2ⁿ`, that is the
difference between impossible and instant — the same repeated-squaring trick that beat linear
time for Fibonacci.
