The tree picture says what the subproblems should be. Every subtree multiplies a block of
neighbouring matrices, so make one subproblem per block.

## The subproblem

A **stretch** is a block of consecutive matrices `Aᵢ, Aᵢ₊₁, …, Aⱼ` with `1 ≤ i ≤ j ≤ n`.

```
C(i, j) = minimum cost of multiplying  Aᵢ × Aᵢ₊₁ × ⋯ × Aⱼ
```

This needs two indices, and it is worth seeing why. In the knapsack and in edit distance,
every subproblem was a *prefix*: the first `j` items, the first `i` letters. One number
said where it stopped, because it always started at the beginning. A stretch can start in
the middle of the chain, so it needs a number for each end.

The answer to the whole problem is `C(1, n)`.

## The recurrence

Ask the usual question: what was the last decision? Here it is the last multiplication, the
root of the tree. It splits the stretch into two parts at some `k` with `i ≤ k < j`:

```
(Aᵢ ⋯ Aₖ)   and   (Aₖ₊₁ ⋯ Aⱼ)
```

By optimal substructure each part is multiplied in its own cheapest way. Then the two
results are multiplied together. So:

```
C(i, j) = min over i ≤ k < j of { C(i, k) + C(k+1, j) + mᵢ₋₁ · mₖ · mⱼ }
```

| Term | What it is |
| --- | --- |
| `C(i, k)` | cost of the left stretch; its result is one `mᵢ₋₁ × mₖ` matrix |
| `C(k+1, j)` | cost of the right stretch; its result is one `mₖ × mⱼ` matrix |
| `mᵢ₋₁ · mₖ · mⱼ` | cost of multiplying those two results together |

The base case is `C(i, i) = 0`: a single matrix needs no multiplication.

## Where the three `m`s come from

This is the part that gets misread. Recall that `Aᵢ` is `mᵢ₋₁ × mᵢ`.

- The left result has the rows of its first matrix, `Aᵢ`, which is `mᵢ₋₁`, and the columns
  of its last, `Aₖ`, which is `mₖ`.
- The right result has the rows of `Aₖ₊₁`, also `mₖ`, and the columns of `Aⱼ`, which is
  `mⱼ`.

Multiplying an `mᵢ₋₁ × mₖ` matrix by an `mₖ × mⱼ` matrix costs `mᵢ₋₁ · mₖ · mⱼ`. The
subscript on the first one is `i − 1`, not `i`.

## A tiny check

Two matrices, `A₁` of `50 × 20` and `A₂` of `20 × 1`, so `m = 50, 20, 1`. The only split
is `k = 1`:

```
C(1, 2) = C(1, 1) + C(2, 2) + m₀ · m₁ · m₂ = 0 + 0 + 50 · 20 · 1 = 1,000
```

which is the `pqr` cost of one multiplication, as it should be.

The algorithm does not know which `k` is best. It tries every split and keeps the cheapest.

> What a subproblem is indexed by follows from what the pieces of a solution look like.
> Pieces that always start at the beginning need one index. Pieces that can start anywhere
> need two.
