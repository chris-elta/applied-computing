The lecture defines a tree in one line:

> A **tree** is an undirected graph that is **connected** and **acyclic**.

So a tree joins every vertex to every other and has no cycles. The previous concept showed
that, with positive costs, the cheapest connected network is a tree. These three facts are
what the algorithms rely on.

## Fact 1 · A tree on `n` vertices has `n − 1` edges

Build a tree one edge at a time. Start with `n` separate vertices: `n` pieces. Each edge that
closes no cycle joins two different pieces into one, so the count of pieces drops by exactly
one. You reach a single connected piece after `n − 1` edges. Adding any more edge would join
a piece to itself, which closes a cycle.

This is why both of this week's algorithms **stop after `n − 1` edges**. The four-town answer
had three edges for four towns.

## Fact 2 · Connected plus `n − 1` edges means tree

Any connected, undirected `G = (V, E)` with `∣E∣ = ∣V∣ − 1` is a tree.

If such a graph had a cycle, you could delete one cycle edge and stay connected. That would
leave a connected graph on `n` vertices with only `n − 2` edges. By the counting in Fact 1,
`n − 2` edges leave at least two separate pieces, so that is impossible.

So you can check "is this a tree?" by checking that it is connected and counting its edges.
You never have to search for a cycle.

## Fact 3 · Unique paths

A graph is a tree **if and only if** there is exactly one path between every pair of vertices.

- *Tree ⇒ unique paths.* At least one path, because it is connected. If there were two
  different paths from `u` to `v`, then going out along one and back along the other would
  close a cycle.
- *Unique paths ⇒ tree.* There is a path, so it is connected. A cycle would give two routes
  between any two of its vertices, so there is no cycle.

Fact 3 matters for Kruskal's algorithm. Adding edge `(u, v)` creates a cycle exactly when `u`
and `v` already have a path between them.

| Fact | What it buys you |
| --- | --- |
| `n − 1` edges | a stopping rule |
| connected + `n − 1` edges ⇒ tree | a test that does not search for cycles |
| unique paths | "closes a cycle" means "already connected" |

> A tree has exactly enough edges to connect its vertices and none to spare. Each fact above
> says that in a different way.
