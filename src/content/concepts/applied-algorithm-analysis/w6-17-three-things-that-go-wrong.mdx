Three mistakes that are still being made after one careful reading of the material. The
first two carried over from week 5. The third now has a sharper example.

## 1 · Reading the answer off the wrong cell

Re-read your definition of `dp[i]`, then ask which cell holds the answer. The definition
decides, not habit.

| Table | A cell means | The answer is |
| --- | --- | --- |
| `K(w, j)` | best value, capacity `w`, first `j` items | the corner `K(W, n)` |
| `C(i, j)` | cheapest cost of the stretch `i` to `j` | `C(1, n)`, the top-right corner |
| `I(u)` | largest independent set below `u` | `I(r)` at the root |
| LIS `dp[i]` | longest increasing subsequence *ending at* `i` | the maximum over all cells |

The longest increasing subsequence from week 5 is the case where `dp[n−1]` is wrong. And
notice that for the matrix chain, "the last cell" is not at the bottom-right of anything:
it is wherever the definition puts the whole chain.

## 2 · Treating memoization and tabulation as different algorithms

They share the same subproblems, the same recurrence and the same asymptotic cost. What
differs is the order of evaluation, the constants, the use of the call stack, and whether
subproblems that turn out not to be needed get solved.

This week adds a practical angle. The matrix-chain table has an awkward fill order, by
length. A memoized version never has to work that order out: it recurses on whatever the
recurrence asks for and the order emerges. It is still the same `O(n³)` algorithm.

## 3 · Believing a recurrence because it passes the examples

The one-index `K(w)` is a correct recurrence, for the unlimited-copies problem. Applied to
the one-of-each problem it gives the right answer whenever no item happens to be worth
taking twice, and so it can pass a set of small tests.

With the lecture's items and a 5-pound bag, `K(5) = 23`, which is B and D: one of each, and
also the correct 0/1 answer. With a 10-pound bag it returns 48, using D twice, where the
correct 0/1 answer is 46.

More test cases are not the cure, since a few more might pass as well. Check the
**definition of the subproblem** first. "Best value in a bag of capacity `w`" says nothing
about which items remain. A recurrence built on it cannot respect a one-copy limit,
whatever it prints.

> Every one of these is caught the same way: say in one sentence what a cell means, and
> check each term of the recurrence, and the cell you return, against that sentence.
