The adjacency matrix spends a cell on every pair that is *not* an edge. The other way to
store a graph keeps only what is there: for each vertex, a list of its neighbors.

```
Adj[1] → 2
Adj[2] → 1, 3, 4
Adj[3] → 2, 4
Adj[4] → 2, 3
```

This is the same four-vertex graph as the matrix example, with edges `1–2`, `2–3`, `2–4`
and `3–4`. The lists hang off an array (or dictionary) indexed by vertex, so `Adj[v]` is
found in one step.

## Counting the entries

Add up the list lengths: `1 + 3 + 2 + 2 = 8`. The graph has four edges, so that is `2m`.
Each undirected edge `{2, 4}` appears twice — once as 4 in vertex 2's list, once as 2 in
vertex 4's. Each list's length is that vertex's degree, so this is the same fact as the
matrix's row sums:

```
Σ deg(v) = 2m        (undirected)
```

In a **directed** graph, store only **outgoing** neighbors: `Adj[v]` holds every `w` with
an edge `v → w`. Each edge then appears once, in its tail's list, for `m` entries in all.
The search algorithms this week all use this outgoing-list convention.

## What it costs

| part | how many |
| --- | --- |
| list heads, one per vertex | `n` |
| neighbor entries | `2m` undirected, `m` directed |
| **total** | **`Θ(m + n)`** |

Why not `Θ(m)`? Because a vertex with no neighbors still has a list — an empty one. A
million vertices and no edges need a million list heads. The `n` term is what keeps the
bound honest for graphs with isolated vertices.

Compare that with the matrix's `Θ(n²)`. For a sparse graph with `m = O(n)`, the list uses
space linear in `n`; the matrix uses space quadratic in it. The gap is not a constant
factor. A road network with a million intersections and a few million roads fits in a few
million list entries, against a trillion matrix cells.

The list also hands over a vertex's neighbors directly: to visit everything next to `u`,
walk `Adj[u]` — `deg(u)` steps. The matrix would make you read a whole row of `n` cells to
find the same few 1s. That difference is what makes graph search linear, a few pages on.

> An adjacency list stores the graph in space proportional to its size, `n + m`, and gives
> each vertex's neighbors without searching for them. It is the default for sparse graphs,
> and every search algorithm this week assumes it.
