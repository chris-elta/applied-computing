      - text: >-

        explains: >-
          `(AB)(x_i) = A(x_i)·B(x_i)` holds pointwise only when both sides are evaluated at the
          *same* `x_i` — value-form multiplication is cheap precisely because it reduces to `m`
          independent single-number multiplications, one per shared point.
      - text: >-
          The points must be the roots of unity specifically
        explains: >-
          The pointwise-multiplication trick works for *any* shared set of evaluation points —
          the roots of unity turn out to be a specially efficient choice, which is the next

          There must be exactly as many points as the degree of the smaller polynomial

**Polynomial interpolation** finds a polynomial that passes through a given set of data
points. For `n+1` points, the unique interpolating polynomial has degree `n` — the smallest
case is familiar: two distinct points determine exactly one straight line, a degree-1
polynomial. Rephrased: **a degree-`n` polynomial is uniquely characterised by its values at
any `n+1` distinct points.**

## Two ways to write down a polynomial

| | Coefficient form | Value form |
| --- | --- | --- |
| what you store | `a_0, a_1, …, a_{n-1}` | `A(x_0), …, A(x_{m-1})` at `m` chosen points |
| evaluating at one point | `O(n)` | free, if it's one of the chosen points |
| multiplying two of them | `O(n²)` | `O(n)` — multiply the values pointwise |

Multiplication is quadratic in one form and linear in the other. So the question is what it
costs to **change form** — and how many points are enough. Careful with the degree: the
product of two degree-`(n−1)` polynomials has degree `2n−2`, so it needs `2n−1` values to be
recoverable. Taking `m = 2n` points is a clean choice that covers that requirement with room
to spare.
