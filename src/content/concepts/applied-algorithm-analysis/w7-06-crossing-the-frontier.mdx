Here is Prim's algorithm as pseudocode. The input is a connected, undirected, weighted graph
`G = (V, E)`.

```
Prim
X := {s}
T := ∅

while X ≠ V do
    // one endpoint in X, one outside
    choose edge e = (v, w) with
        v ∈ X and w ∉ X
        and minimum weight(e)
    add w to X
    add e to T

return T
```

## Reading it line by line

| Line | Meaning |
| --- | --- |
| `X := {s}` | the tree has reached only the start vertex `s` |
| `T := ∅` | no edges selected yet |
| `while X ≠ V` | keep going while some vertex is still unreached |
| `v ∈ X and w ∉ X` | the edge must have exactly one end in the tree |
| `minimum weight(e)` | of all such edges, take the cheapest |
| `add w to X; add e to T` | one new vertex and one new edge per iteration |

Two sets are kept, and it is worth keeping them apart. `X` holds **vertices**: the ones
reached so far. `T` holds **edges**: the ones chosen so far. They grow together, one vertex
and one edge per pass. `T` always has one fewer element than `X`.

## The frontier

Draw a closed curve around `X`. Everything inside has been processed, and `V ∖ X` lies
outside. That curve is the **frontier**, and the edges that cross it are the candidates.

| Kind of edge | Prim's view |
| --- | --- |
| both ends in `X` | already connected; would close a cycle; ignored |
| one end in `X`, one in `V ∖ X` | **crosses the frontier**; a candidate |
| both ends in `V ∖ X` | does not touch the tree yet; ignored for now |

The lecture puts it in one sentence: *every iteration of Prim's algorithm chooses one new
edge crossing from `X` to `V ∖ X`.* Each pass moves one vertex across, so the frontier moves
outward, and some edges change category. An edge that crossed may now have both ends in `X`,
and an edge that was outside may now cross.

## Why the frontier is the important idea

Two later topics rest on it.

- **Running time.** Finding the cheapest crossing edge is the expensive part of each pass.
  Rescanning every edge costs `O(m)` each time. A heap keeps the candidates ready.
- **Correctness.** The frontier is a **cut**: a split of the vertices into two groups. The
  cut property says the cheapest edge across any cut is safe to take, and that is exactly
  what this line of pseudocode chooses.

> Prim's loop is one question asked `n − 1` times: what is the cheapest edge across the
> frontier? Making that question fast gives the running time, and showing the answer is safe
> gives the proof.
