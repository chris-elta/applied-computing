The previous concept ended with an observation: strip the last column from an alignment and
what remains aligns a prefix of one string with a prefix of the other. That observation is
most of the dynamic program. This concept writes it out with the recipe.

## Step 1 — the subproblem

Call the strings `x` and `y`, with lengths `m` and `n`. A **prefix** is a starting piece:
SNO is a prefix of SNOWY.

> `E(i, j)` = the edit distance between `x[1…i]` and `y[1…j]`.

There are `(m + 1)(n + 1)` of these — the "+ 1" because `i` and `j` may be 0, meaning the
empty prefix — and the answer wanted is `E(m, n)`. One index was enough to name a
subproblem for the LIS. Here it takes a pair, because there are two strings to cut.

## Step 2 — what the rightmost column can be

Consider the best alignment of `x[1…i]` with `y[1…j]` and look only at its last column.

| Scenario | Column | Meaning | Cost |
| --- | --- | --- | --- |
| 1 | `x[i]` over `−` | delete `x[i]` | `1 + E(i−1, j)` |
| 2 | `−` over `y[j]` | insert `y[j]` | `1 + E(i, j−1)` |
| 3 | `x[i]` over `y[j]` | match or substitute | `diff(i, j) + E(i−1, j−1)` |

where `diff(i, j)` is 0 if `x[i] = y[j]` and 1 otherwise.

Read each cost as "this column, plus the best way to align whatever is left". In scenario
1 the column used up one letter of `x` and none of `y`, so what is left is `x[1…i−1]`
against `y[1…j]`.

**Is there a fourth scenario?** Try to think of one. The only remaining possibility is a gap
over a gap, and a column like that aligns nothing with nothing — delete it and you have the
same alignment. So the three are exhaustive: the best alignment ends in one of them, and the
recurrence takes the cheapest.

```
E(i, j) = min{ 1 + E(i−1, j),  1 + E(i, j−1),  diff(i, j) + E(i−1, j−1) }
```

This is where "exactly" comes from. The three-edit example for kitten showed one possibility;
the `min` covers all of them, because every alignment has a last column and every last
column is in the table.

## Step 3 — the base cases

```
E(i, 0) = i        E(0, j) = j
```

Where do these come from? They are the only subproblems with nothing smaller underneath.
Turning a prefix of length `i` into the empty string takes `i` deletions. Building a prefix
of length `j` from the empty string takes `j` insertions.

> For problems about two strings, cut both down to prefixes and index the subproblem by the
> pair of lengths. Then ask what the last column — the last decision — could have been.
