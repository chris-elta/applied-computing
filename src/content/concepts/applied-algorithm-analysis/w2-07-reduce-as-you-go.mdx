Modular arithmetic would be worthless if you had to compute the answer first and reduce it
afterwards. Two numbers make the point:

- `2³⁴⁵` has **104 decimal digits**. Large, but writable.
- In cryptography the *exponent* has hundreds of digits, so `xʸ` would have more digits than
  there are atoms in the observable universe.

So the naive route is not slow. It is impossible.

## The escape

Take `mod N` **after every single step**, never at the end. The substitution rule guarantees
this changes nothing — swapping a number for its remainder is always allowed, so doing it
early is as valid as doing it late.

```
13 × 17 mod 10

the long way:   13 × 17 = 221,  then 221 mod 10 = 1
the short way:  (13 mod 10)(17 mod 10) = 3 × 7 = 21,  then 21 mod 10 = 1
```

Same answer, smaller numbers at every stage.

And the payoff compounds. Because every intermediate value is dragged back below `N`
immediately, **every operation in the whole computation works on `n`-bit numbers**, however
long it runs. The cost per step stays flat; the only thing that grows is how many steps you
do.

## But doesn't the reduction cost something?

The obvious worry is that you have only moved the expense. You have not — a modular operation
costs the same *order* as the ordinary one, and the asymmetry between the two cases is worth
understanding rather than memorising.

**Addition.** Both inputs are below `N`, so `a + b < 2N`. It has overshot by at most **one**
copy of `N`. Reducing means checking whether it reached `N` and, if so, subtracting once.

> add `O(n)` + one subtraction `O(n)` = **`O(n)`**

**Multiplication.** Both inputs are below `N`, so `a · b < N²` — up to `2n` bits, twice the
length. It may have overshot by nearly a *factor* of `N`, so subtraction is hopeless; you
need one full **long division** by `N`.

> multiply `O(n²)` + one division `O(n²)` = **`O(n²)`**

## The two prices everything else is built from

> - One modular **addition** is `O(n)`.
> - One modular **multiplication** is `O(n²)`.

Those are the only unit costs the rest of the week uses. The next two algorithms each take
one of them and multiply by a round count — and that is their entire analysis.
