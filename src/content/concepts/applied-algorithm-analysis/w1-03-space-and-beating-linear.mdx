To fill box `i`, `fib2` reads boxes `i−1` and `i−2`. It never looks further back. So why
keep the rest?

```
function fib4(n)
  if n = 0 return 0
  prev = 0, curr = 1
  for i = 2…n:
    prev, curr = curr, prev + curr
  return curr
```

Two variables — exactly what you would keep on your fingers. Same linear time, no array, no
call stack.

## Saying "how much memory" precisely

Read `Θ(something)` as **"grows in step with something"**:

- `fib2` uses `Θ(n)` space — bigger `n`, proportionally more room.
- `fib4` uses `Θ(1)` space — two variables, whatever `n` is. `Θ(1)` means "does not grow".

The full definition of `Θ` is a few pages away; this reading is what practitioners mean day
to day.

## The catch, which matters more than the algorithm

`Θ(1)` is true only if **one variable costs one unit**, whatever is in it. That is a
convenient fiction. `F(n)` grows exponentially, so writing it down takes about `0.694 × n`
**bits**. `F(1000)` is a 694-bit number; it does not fit where `F(10)` fits.

| what you count | `fib4`'s space |
| --- | --- |
| **words** — variables, any number as one slot | `Θ(1)` |
| **bits** — actual storage | `Θ(n)` |

Neither is wrong; they answer different questions. Confusing them is the most common error
in this part of the subject.

> The second half of the week is what happens when you stop pretending a number costs one
> unit: addition becomes `O(n)` and multiplication `O(n²)`.

## Beating linear

Yes — if you count arithmetic operations. The Fibonacci rule can be written as a small grid
of numbers (a **matrix**) raised to the `n`th power, and powers don't need `n`
multiplications: square, square the result, square that — reaching `n` in about `log n`
steps.

Same caveat, though: those operations act on numbers `0.694n` bits long, so the *bit* cost
is not logarithmic. You meet this squaring trick again on Friday, as fast modular
exponentiation.
