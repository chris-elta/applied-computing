Comparing every vertex works for the bakery's five. A real LP might have thousands of
variables and an astronomical number of vertices. **Simplex** keeps the vertex idea but
visits only some of them.

## The walk

1. **Start** at a feasible vertex.
2. **Move** along an edge to a neighbouring vertex with a better objective value.
3. **Stop** when no neighbouring vertex is better.

## On the bakery

Starting from the origin, one possible route:

| step | vertex | profit |
| --- | --- | --- |
| start | `(0, 0)` | $0 |
| up the `x₂` axis | `(0, 300)` | $1800 |
| along the Deluxe limit | `(100, 300)` | $1900 |

At `(100, 300)` the neighbours are `(0, 300)` at $1800 and `(200, 200)` at $1400. Neither is
better, so simplex stops. It never looked at `(200, 0)`, and it did not need to.

Other routes exist. Starting along the `x₁` axis gives `(0, 0) → (200, 0) → (200, 200) →
(100, 300)`. That takes more steps and reaches the same answer.

## Why stopping locally is safe

This is the claim that makes simplex correct:

> For a linear objective on this convex polygon, no improving edge means the vertex is
> globally optimal.

The reason is the shape. On a convex region, if some better point existed anywhere, the
segment from the current vertex to it would lie inside the region. Along that segment a
linear objective changes at a steady rate, so it would rise immediately on leaving the
vertex. Some edge out of the vertex would then have to improve too. Since none does, nothing
better exists.

On a non-convex region, or with a curved objective, a walk like this can get stuck on a
local peak. Linearity and convexity rule that out.
