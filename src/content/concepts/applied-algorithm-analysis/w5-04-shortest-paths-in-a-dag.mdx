Here is a small road map with one-way streets and no way to drive in a circle. Six places —
`S`, `A`, `B`, `C`, `D`, `E` — and eight roads with lengths:

| From | To | Length | | From | To | Length |
| --- | --- | --- | --- | --- | --- | --- |
| `S` | `A` | 1 | | `A` | `B` | 6 |
| `S` | `C` | 2 | | `B` | `D` | 1 |
| `C` | `A` | 4 | | `B` | `E` | 2 |
| `C` | `D` | 3 | | `D` | `E` | 1 |

A graph like this, with arrows and no cycles, is a **dag**. Its special property is that the
nodes can be **linearized**: laid out on a line so that every edge points left to right. For
this one, `S, C, A, B, D, E` works. If you have met topological sort, this is the same
thing.

## One node at a time

Take `D`. The only roads into it come from `B` and `C`, so any route to `D` ends with one of
those two edges. Write `dist(x)` for the length of the shortest route from `S` to `x`. Then:

```
dist(D) = min{ dist(B) + 1, dist(C) + 3 }
```

This is only useful if `dist(B)` and `dist(C)` are already known. In the linearized row both
sit to the left of `D`. That is what the order is for.

## The same relation, everywhere

Nothing about `D` was special. Every node's distance is a `min` over the edges coming into
it:

```
dist(S) = 0; every other dist(·) = ∞
for each node v other than S, in linearized order:
    dist(v) = min over every edge u → v of dist(u) + length(u, v)
```

Run it along the row:

| Node | Candidates | `dist` |
| --- | --- | --- |
| `S` | start | 0 |
| `C` | `S`: 0 + 2 | 2 |
| `A` | `S`: 0 + 1 · `C`: 2 + 4 | 1 |
| `B` | `A`: 1 + 6 | 7 |
| `D` | `B`: 7 + 1 · `C`: 2 + 3 | 5 |
| `E` | `B`: 7 + 2 · `D`: 5 + 1 | 6 |

Notice that the order is not "nearest first": `C` is processed before `A` although `A` is
closer. The order only has to respect the arrows.

Each node is visited once and each edge is looked at once, so the cost is `O(|V| + |E|)`.

> Shortest paths in a dag is easy for exactly one reason: there is an order in which every
> value you need has already been computed. The next concept shows that this is not a
> property of graphs — it is what every dynamic program relies on.
