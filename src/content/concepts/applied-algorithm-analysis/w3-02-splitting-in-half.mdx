Week 2 left multiplication at `O(n²)` — schoolbook, Al-Khwarizmi and the recursion all cost
the same, and beating them needed "a genuinely different idea". This is that idea.

Let `x` and `y` be two `n`-bit integers, with `n` a power of 2 for convenience. (The general
case is similar and does not change the analysis.)

## Split each number in half

Cut the bits of each number down the middle:

```
x = 2^(n/2)·xL + xR
y = 2^(n/2)·yL + yR
```

`xL` is the left half of the bits, `xR` the right half, and the left half is shifted back up
into place by the power of two. Worth checking on a real number:

```
x = 10110110 = 182     xL = 1011 = 11     xR = 0110 = 6
                       11 · 16 + 6 = 182  ✓
```

## The product, rewritten

Multiply the two split forms out:

```
xy = (2^(n/2)·xL + xR)(2^(n/2)·yL + yR)
   = 2ⁿ·xL·yL + 2^(n/2)·(xL·yR + xR·yL) + xR·yR
```

Now audit what that costs. The additions are linear. The multiplications by powers of 2 are
**left-shifts** — appending zeros — so they are linear too. Everything cheap.

What is left is four multiplications of `n/2`-bit numbers: `xL·yL`, `xL·yR`, `xR·yL`,
`xR·yR`.

## Writing the cost as a recurrence

Let `T(n)` be the running time on `n`-bit inputs. The algorithm does four half-size
multiplications plus linear work, so:

```
T(n) = 4T(n/2) + O(n)
```

This is a **recurrence** — the cost at size `n` expressed in terms of the cost at smaller
sizes. It is the central object of this week.

Read the two terms separately, because conflating them is the most expensive mistake in this
material:

- **`4T(n/2)`** — the recursive work: four subproblems, each half the size.
- **`O(n)`** — what *this call alone* does: splitting the input and recombining the results.
  Not the total, and not anything the children do.

Whether this recurrence is actually an improvement is the next question, and the answer is
not the one most people expect.
