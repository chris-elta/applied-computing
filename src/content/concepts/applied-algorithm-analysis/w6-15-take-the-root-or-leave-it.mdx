To use dynamic programming on a tree, first give it a top. Pick any vertex as the root.
The answer does not depend on which one. Now every vertex `u` has a subtree hanging below
it: `u`, its children, their children, and so on.

## The subproblem

```
I(u) = size of the largest independent set in the subtree below u
```

The answer for the whole tree is `I(r)` at the root `r`.

## The order

Suppose `I(w)` is already known for every vertex `w` below `u`. Then `I(u)` can be worked
out from those. So children must be finished before their parents. A walk of the tree that
does this is a **post-order traversal**: leaves first, root last.

## Two cases

Either `u` is in the independent set or it is not. This is the committee trade-off, applied
to one vertex.

| Case | Consequence | Value |
| --- | --- | --- |
| `u` included | no child may be used, so jump to the grandchildren | 1 + the sum of `I(w)` over grandchildren `w` |
| `u` excluded | each child's subtree can use its own best answer | the sum of `I(w)` over children `w` |

Take the better of the two:

```
I(u) = max{ 1 + ∑ I(w) over grandchildren w of u,
                ∑ I(w) over children w of u }
```

Why are sums allowed? The subtrees below different children share no vertices and no edges
with each other. An independent set chosen in one cannot conflict with one chosen in
another, so the best for each can be added together.

A leaf has no children and no grandchildren. Both sums are empty, so `I(leaf)` is
`max{1 + 0, 0} = 1`: take the leaf.

## The bug to avoid

A common mistake is to take `u` and then add the **children's** `I` values:

```
1 + ∑ I(w) over children w        ← wrong
```

`I(w)` is the best answer for the subtree below `w`, and that best answer may include `w`
itself. But `w` is joined to `u`. Taking `u` rules out every child, and `I(w)` does not
know that.

The grandchildren's values are safe. A grandchild is not joined to `u`, and its subtree
contains none of `u`'s children. They are the nearest subproblems that are guaranteed to be
compatible with taking `u`.

## Cost

Each vertex's `I` value is read at most twice: once by its parent, in the "excluded" sum,
and once by its grandparent, in the "included" sum. So the total work is proportional to
the number of vertices: linear time, `O(∣V∣)`.

> A subproblem's value can be reused only where its definition matches what you need.
> `I(w)` means "best in this subtree, with `w` free to be used". When `w` is not free,
> reach past it to subproblems that do not care.
