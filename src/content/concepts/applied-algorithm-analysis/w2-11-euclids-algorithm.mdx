The **greatest common divisor** of two integers is the largest whole number that divides both
exactly. ("`d` divides `a`" means `a` is a whole number of `d`s — 3 divides 12, 5 does not.)

For 12 and 18 you can just list them:

```
divisors of 12:  1, 2, 3, 4, 6, 12
divisors of 18:  1, 2, 3, 6, 9, 18
in common:       1, 2, 3, 6      →  gcd = 6
```

Now try that on two 100-digit numbers. You cannot — you would have to factorise them both,
and nobody knows how to do that quickly. A completely different idea is needed.

## Euclid's rule

> For integers `a ≥ b > 0`:  `gcd(a, b) = gcd(b, a mod b)`

Try one step: `gcd(1035, 759)`. Since `1035 mod 759 = 276`, that equals `gcd(759, 276)`. The
numbers got smaller and the answer did not change. Repeat until something hits zero.

## Why it holds — a technique worth stealing

The proof does something clever. Instead of reasoning about the *greatest* common divisor, it
shows the two pairs have **exactly the same set** of common divisors. Equal sets must have
equal largest members, so the greatest one is preserved.

Write `a = qb + r`, where `r = a mod b`. Take any number `d`:

- **If `d` divides `a` and `b`** — it divides `qb`, so it divides `a − qb = r`. So `d` is a
  common divisor of `b` and `r`.
- **If `d` divides `b` and `r`** — it divides `qb + r = a`. So `d` is a common divisor of `a`
  and `b`.

Every common divisor of one pair is a common divisor of the other. Same set, same greatest
member. ∎

> Notice the proof never mentions "greatest" until the final sentence. Turning a question
> about a maximum into a question about a whole set is a move worth remembering.

## The algorithm

```
function Euclid(a, b)
  Input:  Two integers a and b with a ≥ b ≥ 0
  Output: gcd(a, b)

  if b = 0: return a
  return Euclid(b, a mod b)
```

Two lines. It stops because `b` strictly decreases every call and stays non-negative, so it
must reach 0.

That proves it *finishes*. It says nothing about how **soon** — and that is the next page.
