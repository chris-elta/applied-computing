          every coin stays available. And a bound containing the value `A` is
          pseudo-polynomial, not polynomial.
      - text: >-
          A stretch of the coin list from `i` to `j`; `O(n³)`
        explains: >-
          Stretches suit problems whose solutions split a sequence into a left part and a

        explains: >-
          That enumerates which denominations are used rather than naming a subproblem,

          that shrinks.
    work: |-
      Step 1: `M(a)` = fewest coins that make amount `a` exactly.
      Step 2: `M(a) = 1 + min over coins c ≤ a of M(a − c)`; `M(0) = 0`.
      Step 3: fill `a = 1, 2, …, A`; the answer is `M(A)`.
      Cells: `A`. Work each: up to `n` coins. Total `O(nA)`.
      `A` is a value, not a length → pseudo-polynomial.

Two weeks, eight problems, one method.

## The table

| Problem | Subproblem is indexed by | Time |
| --- | --- | --- |
| Fibonacci | one integer | `O(n)` |
| Shortest path in a dag | a vertex | `O(∣V∣ + ∣E∣)` |
| Longest increasing subsequence | an ending position | `O(n²)` |
| Edit distance | a pair of prefixes | `O(mn)` |
| Knapsack, unlimited copies | a capacity | `O(nW)` |
| Knapsack, one of each | a capacity and a position in the item list | `O(nW)` |
| Chain matrix multiplication | a stretch of the chain | `O(n³)` |
| Independent set in a tree | a subtree | `O(∣V∣)` |

The middle column is the exam skill. Name what the subproblem is indexed by, and the
recurrence usually follows. The three questions — subproblem, recurrence, filling order —
stayed the same all week. What changed was the index.

## Check yourself

Try each before reading the answer under it.

**Why does knapsack with repetition need one index and without repetition need two?**
With repetition, every item is still available after a take, so the bag size alone
describes what is left. Without repetition, you must also know which items remain: that is
`j`.

**`O(nW)` looks polynomial. Why is it not?**
Add three zeros to `W`: you type only three more digits, but the table gets 1,000 times
wider. The work follows the value of `W`, not the number of digits it takes to write it.

**Why must the chain matrix table be filled by increasing length rather than row by row?**
`C(i, j)` reads shorter stretches only. Row by row, `C(1, 4)` would need `C(2, 4)`, which
is still empty.

**In the tree problem, why does the "take `u`" case sum over grandchildren instead of
using the children's `I` values?**
A child's `I(w)` may include `w`, and `w` is joined to `u`. Grandchildren are the nearest
free vertices.

## What carried over from week 5

- **The dag.** The knapsack with repetition is literally a longest path through one.
- **Cost and solution are different things.** The one-row knapsack gives the value and
  forgets the items; the walk back needs the 2-D table.
- **Overlap.** 1.7 billion bracketings share 210 stretches.
