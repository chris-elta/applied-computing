## The week in one table

| part | the feasible answer | the bound | when they meet |
| --- | --- | --- | --- |
| LP | a feasible plan | a vertex at least as good as every point | compare vertices: the best one is optimal |
| max flow | a feasible flow | any s–t cut's capacity | no augmenting path: flow equals cut |
| matching | a matching, as a unit flow | a cut in the matching network | max matching size equals max flow |

## Linear programs

- **Model:** decision variables, a linear objective, linear constraints, variable domains.
  Every term is a fixed number times a single variable.
- **Relaxation:** dropping integrality gives an upper bound for a max problem. Rounding is not
  a method.
- **Geometry:** the feasible region is convex, because a weighted average of feasible points
  is feasible.
- **Corners:** for a nonempty bounded region, some vertex is optimal, because every point is a
  weighted average of vertices and a linear objective averages the same way. Ties along an
  edge are possible.
- **Failure modes:** infeasible, with an empty region, or unbounded, with no largest value.
  An unbounded region alone does not make the objective unbounded.
- **Simplex:** walk to better neighbouring vertices and stop when none improves. For an LP,
  that is the global optimum.
- **Forms:** negate to switch max and min, add slack or subtract surplus to make equations,
  negate to turn `≥` into `≤`, and split a free variable into `u − v`.

## Network flow

- **LP:** one variable per edge, `0 ≤ f ≤ c`, with conservation at intermediate nodes.
- **Cuts:** every flow is at most every cut. Count only edges from `S` to `T`.
- **Residual graph:** a forward edge `c − f` to add, a backward edge `f` to cancel.
- **Ford–Fulkerson:** augment by the bottleneck along any residual path, and stop when none
  remains.
- **Max-flow min-cut:** at the end, the reachable set is a cut with full outgoing and empty
  incoming edges, so flow equals cut.

## Matching

Add `s` and `t`, give every edge capacity 1, and run max flow. Integer capacities give an
integer flow, and its middle edges are the matching.

## The mistakes worth checking for

| mistake | correction |
| --- | --- |
| "an optimum must be a vertex" | *some* optimum is a vertex. Edges can tie. |
| "unbounded region, so no maximum" | only if the objective improves in that direction |
| counting `T → S` edges in a cut | only `S → T` capacities count |
| dropping backward residual edges | the algorithm can get stuck below the maximum |
| `Δ` from the original capacities | `Δ` is the smallest *current residual* capacity |
| rounding an LP answer | it can break a constraint or miss the integer optimum |

> To prove an answer optimal, give a feasible answer and a bound every feasible answer must
> obey. When the two meet, you have both the answer and its proof. This week that was a
> vertex for an LP, a cut for a flow, and a cut again for a matching.
