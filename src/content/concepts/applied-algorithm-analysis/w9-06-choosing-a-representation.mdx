Neither representation wins everywhere. The table compares them for an undirected graph,
assuming you can reach any vertex's list or row directly.

| operation | unsorted adjacency lists | adjacency matrix |
| --- | --- | --- |
| space | `Θ(n + m)` | `Θ(n²)` |
| is `{u, v}` an edge? | `O(1 + deg(u))`, scanning `Adj[u]` | `O(1)`, one cell |
| list `u`'s neighbors | `Θ(deg(u))` entries | `Θ(n)` cells |
| insert an edge known to be absent | `O(1)` with linked lists | `O(1)` |
| delete `{u, v}` | `O(deg(u) + deg(v))` by scanning; `O(1)` with a handle and back-references | `O(1)` |
| add a vertex | amortized `O(1)` with a dynamic array | `Θ(n²)` if the matrix is reallocated |
| store weights | in each neighbor or edge record | in each cell, with a marker for no edge |

## Reading the table

Two rows decide almost every choice.

**Listing neighbors.** This is the operation graph search does over and over, and the
representations differ by more than a constant. Lists cost the degree; the matrix costs `n`
every time, because it has to read the whole row to find which cells hold 1. On a sparse
graph that is the difference between linear and quadratic total time — the next section
counts it exactly.

**Checking one edge.** Here the matrix wins: one cell, `O(1)`. Lists have to scan. If an
algorithm's inner loop asks "are these two joined?" for arbitrary pairs, a matrix — or
lists replaced by hash sets, which give *expected* `O(1)` checks — pays off.

## The small print

- "Insert" assumes the edge is not already there. Checking for a duplicate first adds a
  lookup.
- Fast deletion in lists needs the extra references from the previous page. Plain lists
  scan.
- Adding a vertex to a matrix means a new row and column. If that means copying the whole
  grid into a bigger one, it costs `Θ(n²)`; other growth strategies cost differently.

## A rule of thumb

| graph | likely choice |
| --- | --- |
| sparse, and you traverse it | adjacency lists |
| dense, or you test arbitrary pairs often | adjacency matrix |
| sparse, and you test pairs often | lists of hash sets |

> Choose the representation by the operation your algorithm repeats. Traversal repeats
> "give me the neighbors", which lists do in `deg(u)` and a matrix does in `n` — so for
> graph search, the answer is almost always lists.
