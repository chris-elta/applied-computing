The label `l(e) = 3` says how far `e` is. It does not say *which* three edges to take. To
recover an actual shortest path, record one more thing during BFS: who discovered each
vertex.

```
1   parent[v] := NIL for every vertex v
2   when w is first discovered from v:  parent[w] := v
```

Line 2 sits right beside the label assignment — the same moment, `w` is marked, labelled
and queued. On the example graph, BFS records:

| vertex | `s` | `a` | `b` | `c` | `d` | `e` |
| --- | --- | --- | --- | --- | --- | --- |
| parent | NIL | `s` | `s` | `a` | `b` | `c` |

## Walking back

Each parent pointer is one edge back toward `s`. To find a path to a target `t`, start at
`t` and follow them until they run out:

```
3   x := t
4   while x ≠ NIL do  add x to the list
5       x := parent[x]
6   reverse the list
```

From `e`:

| `x` | list so far | next `x` |
| --- | --- | --- |
| `e` | `e` | `parent[e] = c` |
| `c` | `e, c` | `parent[c] = a` |
| `a` | `e, c, a` | `parent[a] = s` |
| `s` | `e, c, a, s` | `parent[s] = NIL` — stop |

Reversed: **`s → a → c → e`**, three edges, matching `l(e) = 3`.

## Why reverse?

Parents point *toward* the start, so the walk can only begin at the target. The list comes
out target-first. Reversing it is one pass over a list as long as the path. Alternatively,
push onto a stack and pop — same effect.

## Why it always works

Along the parent chain, every step decreases the distance label by exactly one: `parent[w]
= v` was set together with `l(w) = l(v) + 1`. A sequence of numbers that drops by one each
step cannot loop, and must reach 0 — which only `s` has. So the walk always ends at `s`,
with exactly `l(t)` edges: a shortest path.

Two edge cases:

- The path to `s` itself is just `[s]`, with zero edges, since `parent[s] = NIL`.
- A target whose label is still `+∞` was never discovered, has no parent, and has no path.

## What it costs

One extra field per vertex: `O(n)` space. Recording parents adds constant time per
discovery, and walking back costs time proportional to the path's length.

A different neighbor order could give `e` the parent `d` instead, producing the path
`s → b → d → e`. That is equally short. BFS guarantees *a* shortest path, not a particular
one.

> Record who discovered each vertex, and every vertex points one step back toward `s`.
> Walking those pointers from the target and reversing the result gives a shortest path.
