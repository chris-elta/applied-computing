Double the left column, halve the right (rounding down), stop when the right reaches 0, then
add up the left-hand values whose right-hand partner was **odd**.

| `x` — double | `y` — halve | odd? | keep |
| --- | --- | --- | --- |
| 11 | 13 | yes | + 11 |
| 22 | 6 | no | — |
| 44 | 3 | yes | + 44 |
| 88 | 1 | yes | + 88 |
| — | 0 | stop | **= 143** |

`11 × 13 = 143`. That last row is not a fifth kept value — it is the three kept values added
together: `11 + 44 + 88`.

## Why it works

The rows kept are exactly the 1-bits of `13 = 1101₂`.

That is not a coincidence, and it is the whole trick: **halving `y` and testing for odd is
reading the bits of `y` from the right**, while doubling `x` is the shift. So this is binary
shift-and-add, written about a thousand years before binary notation existed. The figure on
slide 15 lines the rows up against the bits — worth running once.

## The same thing, as a recursion

```
function multiply(x, y)
  if y = 0: return 0
  z = multiply(x, ⌊y/2⌋)
  if y is even: return 2z
  else: return x + 2z
```

Trace it and the table reappears:

```
multiply(11, 13)   y odd  → 11 + 2·multiply(11, 6)
multiply(11, 6)    y even →      2·multiply(11, 3)
multiply(11, 3)    y odd  → 11 + 2·multiply(11, 1)
multiply(11, 1)    y odd  → 11 + 2·multiply(11, 0)
multiply(11, 0)          → 0
back up:  0 → 11 → 33 → 66 → 143
```

`143 = 11 + 4·11 + 8·11 = 11 + 44 + 88` — the three rows the table kept. The `44` and `88`
are the single `x` added deep in the recursion, doubled once per level on the way back out.

## Three costumes, one algorithm

Halving `y` is the table's right column. Doubling is its left column. Adding `x` when `y` is
odd is keeping the row.

So this is not a third method. There are `n` rounds because `y` halves each time, and each
round adds two `n`-bit numbers at `O(n)`:

> `n` rounds × `O(n)` per round = **`O(n²)`** — the same as schoolbook.

Three presentations that look nothing alike, one cost. Beating `O(n²)` needs a genuinely
different **idea**, not a rearranged ritual — divide and conquer, as Karatsuba's algorithm,
in a later week.
