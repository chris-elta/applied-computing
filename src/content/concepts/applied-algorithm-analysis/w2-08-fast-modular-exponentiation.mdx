Compute `xʸ mod N` for enormous `x`, `y` and `N`. This is the operation at the heart of RSA
and Diffie–Hellman, so it has to be genuinely fast.

## Why the obvious method fails

The previous page fixed the *size* problem: reduce after every step and nothing exceeds `N`.
So multiply `x` by itself, reducing each time. Every value stays small. Where is the catch?

**The number of operations.** That does `y − 1` multiplications, and `y` has hundreds of
digits — something like `2⁵⁰⁰` of them. The values are under control; the **count** is not.
Fixing counts is what algorithms are for.

## Halve the exponent instead of decrementing it

Squaring **doubles** an exponent, so halving is the way back down:

```
x¹⁶ = (((x²)²)²)²
```

Four squarings, not fifteen multiplications: 2 → 4 → 8 → 16.

```
function modexp(x, y, N)
  if y = 0: return 1
  if y is even:
    z = modexp(x, y/2, N)
    return z·z mod N
  else:
    z = modexp(x, y−1, N)
    return x·z mod N
```

Even `y`: compute the half power, square it. Odd `y`: take one factor of `x` out, leaving an
even exponent. Reduce mod `N` after every step, so nothing ever exceeds `N`.

> This is the same shape as `multiply` from the multiplication section, with *double*
> replaced by *square* and *add `x`* by *multiply by `x`*. Multiplication is repeated
> addition; exponentiation is repeated multiplication; the halving trick works for both.

## The cost

Let `n` be the bit length of `max(x, y, N)`.

**How many calls?** An odd step drops `y` by 1, and the step right after it halves. So `y` at
least halves every two calls, and an `n`-bit `y` halves at most `n` times — **at most `2n`
calls**, which is `O(n)`.

**How much per call?** One modular multiplication of numbers below `N`: `O(n²)`.

> `O(n)` calls × `O(n²)` per call = **`O(n³)`**

Set that against the naïve count of `y − 1 ≈ 2ⁿ` multiplications. Repeated squaring turns an
**exponential** count into a **cubic** one, and that single change is what makes public-key
cryptography possible. On 500-bit numbers, `O(n³)` is around 10⁸ word operations — fast,
while `2⁵⁰⁰` is not a number of operations anything will ever perform.
