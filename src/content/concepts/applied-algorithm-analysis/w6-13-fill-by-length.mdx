Every table so far this term was filled left to right, or row by row. This one cannot be.

Try rows. To fill `C(1, 4)`, at the end of row 1, the recurrence reads `C(2, 4)` and
`C(3, 4)`. Those sit in rows 2 and 3, which have not been started. Row by row fails.

## What a cell actually depends on

`C(i, j)` reads `C(i, k)` and `C(k+1, j)`. Both are pieces of the stretch from `i` to `j`,
so both are **shorter** than it. That is the only dependency there is. Any order that
finishes all the short stretches before the longer ones is a valid linearization of the
dag.

```
// step 1: length-1 stretches cost nothing
C(1,1) = C(2,2) = … = C(n,n) = 0

// step 2: longer stretches, shortest first
for len = 2 to n:
    for i = 1 to n − len + 1:
        j = i + len − 1
        C(i, j) = min over k = i … j−1 of
                      C(i, k) + C(k+1, j) + m[i−1]·m[k]·m[j]
return C(1, n)
```

| Variable | Meaning |
| --- | --- |
| `len` | how many matrices are in the stretch |
| `i` | where the stretch starts |
| `j` | where it ends, so `j = i + len − 1` |
| `k` | where the last multiplication splits it |

`i` stops at `n − len + 1` so that `j` never goes past `n`.

## The order for four matrices

```
len 1:  C(1,1)  C(2,2)  C(3,3)  C(4,4)     = 0
len 2:  C(1,2)  C(2,3)  C(3,4)
len 3:  C(1,3)  C(2,4)
len 4:  C(1,4)                              ← the answer
```

Each line is one diagonal of the triangular table, starting from the main diagonal and
moving up and to the right. The answer is the last cell filled, alone in the corner.

## Cost

- **Cells.** One per stretch with `i ≤ j`: about `n²/2` of them.
- **Work per cell.** A stretch of `len` matrices has `len − 1` places to cut, never more
  than `n − 1`. For instance `C(1, 4)` is `A B C D`, cut as `A | BCD`, `AB | CD` or
  `ABC | D`: three tries. Each try is a fixed amount of work: read two cells, multiply,
  add.
- **Total.** Three nested loops, `len`, `i` and `k`, each up to `n`. Time `O(n³)`, memory
  `O(n²)`.

Unlike the knapsack bound, this one is honestly polynomial. `n` counts the matrices, so it
is a measure of how much input there is. The dimensions themselves never enter the running
time.

## Why it is worth it

For 20 matrices there are `20 × 21 / 2 = 210` stretches, each with at most 19 splits: under
4,000 steps. The alternative was checking 1,767,263,190 bracketings.

The saving comes from overlap. The same stretch appears in many different trees, and the
table computes its cost once.

> The fill order is not a convention. It is read off the recurrence: find what each cell
> depends on, and finish those first. When cells depend on shorter stretches, you fill by
> length.
