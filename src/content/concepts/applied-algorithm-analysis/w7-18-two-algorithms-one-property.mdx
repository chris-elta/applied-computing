The cut property says the cheapest edge across a cut is safe, as long as the cut keeps the
already-selected components in one piece. Neither algorithm mentions cuts. Both are still
taking the cheapest edge across a cut at every step. They differ in which cut it is.

## Prim: the frontier is the cut

| | |
| --- | --- |
| the two sides | `X`, the vertices already in the tree, and everything outside `X` |
| the choice | the cheapest edge leaving `X` |
| components kept intact? | yes: every selected edge has both ends in `X` |

This is the frontier from the pseudocode. Prim's rule, "the cheapest edge with one end in `X`
and one outside", is the cut property applied to the cut `X | V ∖ X`. Each step adds one
vertex across it, and the frontier moves outward.

## Kruskal: one component against the rest

| | |
| --- | --- |
| the two sides | the current component of one endpoint `u`, and all other vertices |
| the choice | the next sorted edge that joins two different components |
| components kept intact? | yes: `u`'s component is on one side, and every other component lies wholly on the other |

The less obvious part is why the edge Kruskal takes is the *cheapest* across this cut.
Suppose some edge `f` leaving `u`'s component were cheaper than `(u, v)`. Then `f` came
earlier in the sorted list. When it was examined, its endpoints were in different components,
because components only grow, and they are separate now. So Kruskal accepted `f`, which
put its far endpoint in `u`'s component. Then `f` does not cross the cut, which contradicts
the assumption. So no cheaper crossing edge exists.

The sorted order is what does the work. Kruskal never compares edges across a cut. It takes
edges cheapest first, and that order guarantees each accepted edge is the cheapest across the
right cut.

## Worked: Kruskal's third edge

On the five-vertex graph, Kruskal has `(b, e)` 1 and `(a, c)` 2 when it takes `(b, c)` 3.
Use `b`'s component `{b, e}` as one side and `{a, c, d}` as the other.

| Crossing edge | Weight |
| --- | --- |
| `(b, c)` | 3 ← cheapest |
| `(a, b)` | 4 |
| `(b, d)` | 5 |
| `(d, e)` | 7 |

`(b, c)` is the cheapest across that cut, as the argument says. The only cheaper edges in
the graph, weights 1 and 2, were accepted earlier and do not cross.

## Same idea, different bookkeeping

> Both algorithms connect across a boundary as cheaply as possible, without splitting a
> component already selected. Prim keeps one boundary and moves it. Kruskal uses a new
> boundary for each edge, around whichever component that edge leaves.

Formal correctness proofs for both are in DPV, *Algorithms*, chapter 5.
