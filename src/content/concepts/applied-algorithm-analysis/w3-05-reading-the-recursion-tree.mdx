Karatsuba's cost is `T(n) = 3T(n/2) + O(n)`. To turn that into an actual bound, draw what the
recursion does: one node per call, children below their parent.

## The vocabulary

- The top node is the **root**; the ones at the bottom that make no further calls are the
  **leaves**.
- A node at **depth `k`** sits `k` steps below the root. The nodes at one depth form a
  **level**.
- The **height** is the depth of the leaves.
- The **branching factor** is how many children each node has — here 3, one per recursive
  call.

## How tall, and how wide

Each call halves the input, so after `k` levels the subproblems have size `n/2ᵏ`. The
recursion stops when that reaches 1, which happens at `k = log₂ n`:

> **Height of the tree = `log₂ n`.**

And since every node has three children, the level at depth `k` contains `3ᵏ` nodes.

Two numbers moving in opposite directions as you descend:

| going down one level | effect |
| --- | --- |
| number of nodes | **× 3** |
| size of each input | **÷ 2** |

Which one wins is the entire question.

## Work at depth `k`

Each subproblem does linear work of its own — identifying its subproblems, and combining
their results. So the total work at depth `k` is:

```
3ᵏ × O(n / 2ᵏ)  =  (3/2)ᵏ × O(n)
```

That step is worth doing slowly. The `n` factors out of the bracket, and the two `k`-powers
collect into a **single ratio**, `3/2`.

Everything now hinges on one number. If the ratio were below 1 the levels would shrink going
down; at exactly 1 every level would cost the same. Here it is `3/2`, comfortably above 1 —
so the levels **grow**, and the bottom of the tree is where the cost lives.
