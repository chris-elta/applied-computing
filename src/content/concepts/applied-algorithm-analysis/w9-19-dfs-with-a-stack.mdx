Recursion hides its stack inside the program. You can keep your own instead, starting from
BFS and changing **two** things:

1. **A stack instead of the queue.** Push adds to the top and pop removes from the top: push
   `a`, then push `b`, and the next pop gives `b`. The newest vertex is handled first, which
   is what makes the search go deep.
2. **Check and mark when a vertex is popped, not when it is pushed.** A vertex may sit on the
   stack several times; only its first pop counts.

Both changes are needed. The first alone does not give DFS — the next page shows why.

## The pseudocode

```
1   mark all vertices as unexplored
2   S := a stack data structure, initialized with s
3   while S is not empty do
4       remove ("pop") the vertex v from the top of S
5       if v is unexplored then
6           mark v as explored
7           for each edge (v, w) in v's adjacency list do
8               add ("push") w onto the top of S
```

Compare it with BFS line by line:

| | BFS | iterative DFS |
| --- | --- | --- |
| structure | queue, oldest out first | stack, newest out first |
| check and mark | when a vertex **joins** (line 7 of BFS) | when a vertex is **popped** (lines 5–6) |
| which neighbors are added | only unexplored ones | **all** of them, even explored ones |
| can a vertex be stored twice? | no | yes; later copies are skipped |

## A run

On the six-vertex graph, pushing neighbors alphabetically (so the last one pushed is on
top):

| pop | explored? | action | stack after (top on right) |
| --- | --- | --- | --- |
| `s` | no | mark; push `a, b` | `a b` |
| `b` | no | mark; push `c, d, s` | `a c d s` |
| `s` | yes | skip | `a c d` |
| `d` | no | mark; push `b, c, e` | `a c b c e` |
| `e` | no | mark; push `c, d` | `a c b c c d` |
| `d` | yes | skip | `a c b c c` |
| `c` | no | mark; push `a, b, d, e` | `a c b c a b d e` |
| `e, d, b` | yes | skip | `a c b c a` |
| `a` | no | mark; push `c, s` | `a c b c c s` |
| the rest | yes | skip | empty |

Marking order: **`s, b, d, e, c, a`**. It differs from the recursive run's `s, a, c, d, e,
b` only because the neighbor order is different. Both are depth-first: each runs a path to
its end before stepping back.

Notice the explored vertices that land on the stack — `s` on top after `b` is processed,
`d` after `e`. They are pushed because line 8 pushes every neighbor, and skipped because
line 5 checks on the pop.

## What it does not give you

This loop gives the DFS *marking* order. It has no moment that corresponds to a recursive
call *returning*, so it does not directly give finishing times. Topological sort needs
those, and uses recursion, or a stack that stores where each vertex was in its list.

> Iterative DFS is BFS with a stack and the mark moved to the pop. Pushing every neighbor
> and skipping explored ones on the way out is deliberate, not waste.
