The previous page set the target: lose one of the four subproblems. Gauss's identity is
exactly the tool, moved from complex numbers to the two halves of an integer.

Instead of four products, compute three:

```
xL·yL       xR·yR       (xL + xR)(yL + yR)
```

The middle term of the expansion then comes for free:

```
xL·yR + xR·yL = (xL + xR)(yL + yR) − xL·yL − xR·yR
```

Two of those three were needed anyway — `xL·yL` and `xR·yR` are the outer terms of the
product. So only `(xL+xR)(yL+yR)` is genuinely new, and recovering the middle term from it
costs two subtractions, which are linear.

**Three multiplications, not four.**

```
T(n) = 3T(n/2) + O(n)
```

One recursive call fewer than before. How much that saves is not obvious, and it is worth
resisting the urge to guess — the recursion tree over the next two pages produces the number,
and it is more convincing watched than asserted.

## The algorithm

```
function multiply(x, y)
  Input:  Positive integers x and y, in binary
  Output: Their product

  n = max(size of x, size of y)
  if n = 1: return xy

  xL, xR = leftmost ⌈n/2⌉, rightmost ⌊n/2⌋ bits of x
  yL, yR = leftmost ⌈n/2⌉, rightmost ⌊n/2⌋ bits of y

  P1 = multiply(xL, yL)
  P2 = multiply(xR, yR)
  P3 = multiply(xL + xR, yL + yR)

  return P1 · 2^n + (P3 − P1 − P2) · 2^(n/2) + P2
```

Three recursive calls — `P1`, `P2`, `P3`. Everything else on the page is addition,
subtraction or shifting, all linear.

> A little history worth having: in 1960 Kolmogorov told a Moscow seminar that multiplying
> two `n`-digit numbers had to cost about `n²` steps. Karatsuba, a student in the room, broke
> the conjecture within a week — using an identity Gauss had applied to complex numbers a
> century and a half earlier.
