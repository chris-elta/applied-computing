Week 1 met four ways to compute a Fibonacci number. Two of them are the two halves of this
concept, so start with the one they both repair.

## The version that repeats itself

```
function fib1(n)
  if n = 0: return 0
  if n = 1: return 1
  return fib1(n−1) + fib1(n−2)
```

This is the definition, typed in. Draw its calls as a tree and `F(n−2)` appears twice,
`F(n−3)` three times, and it gets worse going down. The same subproblems are solved again
and again, and the running time grows as fast as the Fibonacci numbers themselves — about
`1.6ⁿ` calls.

There are only `n + 1` *different* questions being asked. Everything from here is about
answering each one once.

## Bottom-up: tabulation

```
function fib2(n)
  if n = 0 return 0
  create an array f[0…n]
  f[0] = 0, f[1] = 1
  for i = 2…n:
    f[i] = f[i−1] + f[i−2]
  return f[n]
```

Start at the base cases and fill the table forward. **You** choose the order, and it has to
be one in which every cell's inputs are ready before the cell is computed. For Fibonacci
that order is obvious. In real problems it is the hard part, and the shortest-paths concept
shows where it comes from.

Linear in `n`, no recursion, and usually the smaller constants. Since only the last two
entries are ever read, the array can collapse to two variables — the same trick returns for
edit distance.

## Top-down: memoization

```
function fib3(n, memo)
  if n in memo then return memo[n]
  if n ≤ 1 then return n
  memo[n] = fib3(n − 1, memo) + fib3(n − 2, memo)
  return memo[n]
```

Write the recursion the recurrence already gave you, and add a cache so each subproblem is
solved once. Start at the answer and recurse into whatever it needs. Also linear — the
cache prunes the tree from about `1.6ⁿ` nodes to about `n`. The cost is a call stack `n`
frames deep.

## Side by side

| | Bottom-up | Top-down |
| --- | --- | --- |
| Built from | iteration + a table | recursion + a cache |
| Starts at | the base cases | the answer |
| Order of evaluation | you choose it | the recursion finds it |
| Subproblems solved | all of them | only those actually needed |
| Typical strength | constants and memory | quick to derive from the recurrence |

> These are not two algorithms. They are two schedules for evaluating one recurrence: same
> subproblems, same formula, same answers.
