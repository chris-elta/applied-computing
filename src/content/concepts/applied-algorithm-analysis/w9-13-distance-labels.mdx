BFS already finds the layers. To *record* them, add one number per vertex: the label
`l(v)`, holding the distance from `s` found so far.

```
1   mark s as explored, all other vertices as unexplored
2   l(s) := 0,  l(v) := +∞ for every v ≠ s
3   Q := a queue data structure, initialized with s
4   while Q is not empty do
5       remove the vertex from the front of Q, call it v
6       for each neighbor w in Adj[v] do
7           if w is unexplored then
8               mark w as explored
9               l(w) := l(v) + 1
10              add w to the end of Q
```

Only lines 2 and 9 are new. Everything else is plain BFS.

- **Line 2** starts `s` at distance 0 and everything else at `+∞` — "not found yet".
- **Line 9** runs at the moment `w` is discovered from `v`: `w` is one edge further out than
  `v`.

**Postcondition:** for every vertex `v`, `l(v) = dist(s, v)`.

## A run

On the six-vertex graph, neighbors in alphabetical order:

| remove | discovers | labels set |
| --- | --- | --- |
| `s` (0) | `a`, `b` | `l(a) = l(b) = 1` |
| `a` (1) | `c` | `l(c) = 2` |
| `b` (1) | `d` | `l(d) = 2` |
| `c` (2) | `e` | `l(e) = 3` |
| `d`, `e` | — | nothing changes |

`e` is a neighbor of both `c` and `d`, and both have label 2. It takes its label from `c`
only because `c` left the queue first. Either would have given 3.

## Why the first label is the right one

Each label is set **once**, when the vertex is discovered, and never revised. Why can no
later scan improve it? Because BFS finishes a whole layer before starting the next. When
`w` is first discovered from `v`, every vertex closer to `s` than `v` has already been
removed and scanned. If `w` were reachable in fewer steps, one of those earlier vertices
would have discovered it first.

So line 9 never needs a comparison like "if this is shorter". The queue's order guarantees
that the first answer is the best one.

## Reading `+∞` correctly

A label of `+∞` means two different things at two different times:

| when | `l(v) = +∞` means |
| --- | --- |
| during the run | `v` has not been discovered *yet* |
| after the queue empties | `v` is **unreachable** from `s` |

Do not conclude "no path" from an infinite label mid-run.

## What it costs

Lines 2 and 9 add constant work per vertex. The total stays `O(m + n)`. This holds in
directed and undirected graphs, with every edge counting as one step.

> Augmented-BFS sets each vertex's label once, to its parent's label plus one, and that
> first label is already the distance — because BFS never reaches a layer before finishing
> the one before it.
