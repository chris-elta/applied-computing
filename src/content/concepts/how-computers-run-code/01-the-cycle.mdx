A processor has no idea what your program *means*. It runs a loop so simple you could
carry it out on paper: read the next instruction, work out what it says, do it, repeat.

The program counter is the whole plot. It holds one address — the next instruction — and
almost everything else follows from it. Fetch reads that address, decode inspects what
came back, execute does the work, write back stores the answer, and the counter moves on.

## Why the stages are separate

Splitting the cycle into named stages isn't bureaucracy. It's what lets a real CPU be
fast, because the stages use different hardware. While the ALU is executing instruction
three, nothing is stopping the fetch unit from reading instruction four.

That overlap is called **pipelining**, and it's why a chip running at 3 GHz can retire
several instructions per cycle rather than one every five. The cycle in the figure is
the logical story; the physical chip runs five of them at once, staggered.
