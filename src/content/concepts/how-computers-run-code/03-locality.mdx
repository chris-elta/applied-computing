The cache is small — a few megabytes against many gigabytes of memory. It cannot hold
your data. It can only hold a *guess* about which part of your data you'll want next,
and that guess is startlingly crude:

- **Spatial locality** — if you touched an address, you'll probably touch its neighbours.
- **Temporal locality** — if you touched an address, you'll probably touch it again soon.

That's it. No prediction, no learning, no model of your program. Yet it works, because
almost all real code walks arrays, loops over the same variables, and calls the same
functions repeatedly.

## The part that matters to you

The cache is not something you configure. It is something you either cooperate with or
fight, and which one you're doing is decided entirely by your **memory access pattern**.

An array of structs walked in order cooperates. A linked list scattered across the heap
fights. Two implementations of the same algorithm, with identical operation counts, can
differ by an order of magnitude on this alone — which is why "how many operations" is so
often the wrong question.
